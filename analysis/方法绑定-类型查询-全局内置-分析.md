## 0. 一句话总表

| 问题 | 结论 |
|------|------|
| 字符串 / 切片等要不要「看起来自带」属性和方法？ | **要**。这是类型上的固定能力，不是运行时往变量上挂东西。 |
| `length`、`substring`、`replace`、拼接这类能力合理吗？ | **合理**。高频、语义清晰；拼接 / 替换要在语义上标明可能分配或受 capacity 限制。 |
| `typeof` / `type_name` / `size_of` 等做全局、免 import？ | **适合**做成语言内置能力（编译期语义），不必从 std import。 |
| 全局要放多少？ | **少而精**：类型与布局、控制流安全；业务与 IO 进 core / std。 |
| 语言级 `string` 现在定死全套糖？ | **清单可先定**；语言级 `string` 类型本身仍按基础类型缺口文：**自举后再引入类型**。库侧 `String` / `StrView` 的方法面可先作为目标清单。 |
| 命名 | 产品面全称：`length`、`capacity`、`substring` / `subview` 等。 |

**总原则**：体验上「值带着类型的能力」；语义上是 **静态类型决定可用属性与方法**。

## 2. 属性与方法：用户侧语义

### 2.1 期望写法（产品目标）

```x
let s: string = "Hello";       // 语言级 string：自举后目标；当前可用库类型表达同等意图
s = s + " World";              // 拼接：语义上可能分配或受容量限制，须在文档写清
let n = s.length;              // 长度：属性（字段）优先
let part = s.substring(0, 5);  // 子串：方法；优先返回视图语义
let t = s.replace("Hello", "Hi");
```

说明：

- 「变量自动拥有这些方法」在用户心智里成立；在语言语义上应理解为：**该类型固定提供这些成员**，不是动态给单个变量挂表。  
- `length` 写成 **属性**；需要计算、可能失败、可能分配的写成 **方法**。

### 2.2 属性 vs 方法（统一规则）

| 类别 | 形态 | 例子 |
|------|------|------|
| 纯数据、常数时间、布局信息 | **属性** | `.length`、`.capacity`、`.pointer`（若对外暴露） |
| 有计算、可能失败、分配、边界逻辑 | **方法** | `.substring(...)`、`.subview(...)`、`.get(...)`、`.replace(...)` |
| 运算符 | 文档写清成本与失败语义 | `+` 拼接：标明分配或 capacity 失败，禁止假装零成本 |

**禁止**：同一语义长期维护两套正式名字（例如既叫 `length` 又叫短名）；产品面只认全称。

### 2.3 性能（语义层，不论实现）

| 操作 | 用户应理解的成本 |
|------|------------------|
| `.length` | 应视为极低成本（读长度信息或编译期可知的固定长度）。 |
| 返回**视图**的 `substring` / `subview` | 可为零拷贝；成本主要在边界检查。 |
| `replace`、拼接 `+` | 正常情况有**拷贝 / 分配**或**有界缓冲写满失败**；成本来自操作本身，不是「因为有了方法」才变慢。 |
| 虚调用式默认分发 | **不作为默认模型**；默认应是静态、可内联的语义。 |

### 2.4 安全（语义层）

| 点 | 推荐语义 | 避免 |
|----|----------|------|
| 拥有 vs 视图 | 拥有缓冲（如 `String`）与只读 / 借用视图（如 `StrView`、`u8[]`）分开 | 视图看起来像拥有却可悬垂 |
| 子串 | 优先 **视图**，寿命不超过源；需要独立缓冲再显式拷贝 | 默认返回无长度、无寿命的裸指针 |
| 有界 `String`（今日库：固定 capacity） | 拼接 / 替换必须体现 **capacity 与失败** | 假装无限堆串 |
| 可变 | 只读方法与会改缓冲的方法在语义上区分 | 默认暴露可任意改底层字节且无契约 |
| freestanding | 不依赖操作系统的类型能力（长度、视图）可独立存在 | 基础 `.length` 语义却隐含必须链接完整 IO / 堆 |

### 2.5 与语言级 `string` 的关系

| 项 | 决策 |
|----|------|
| 方法 / 属性清单 | 可以对 **库类型 `String` / `StrView`** 先定目标面 |
| 语言关键字类型 `string` / `str` | 仍按 [基础类型缺口](./基础类型缺口与自举时机分析.md)：**自举后再引入** |
| `*u8 + *u8` 运算符糖 | 仍属后期 / leave-off；清单里「拼接」先作为**具名能力**存在 |

## 3. `typeof` 等做成全局内置？

### 3.1 结论

**适合**作为语言全局能力，**不必** `import` 标准库才能用。

| 点 | 说明 |
|----|------|
| 便利 | 类型查询与布局查询极基础，强制 import 别扭 |
| 成本语义 | 应为编译期结果，不在目标程序里留下查询调用 |
| 一致性 | 与「系统语言里的 sizeof 一类能力」同一档 |
| 命名 | 稳定：`typeof`、`type_name`、`size_of`、`align_of`、`offset_of` |

### 3.2 能力分层（只谈产品能力）

| 层级 | 能力 | 特点 |
|------|------|------|
| **编译期（默认）** | `typeof(expr)`、`type_name`、`size_of`、`align_of`、`offset_of` | 零运行时成本；调试与泛型友好 |
| **库（按需 import）** | 今日已有 `core.types` 一类布局查询 | 与未来语言内置能力应语义一致，避免两套用户故事 |
| **显式运行时（可选、更晚）** | 装箱后的 `Any` / 类型标识 | 只有真正需要运行时类型信息时才用 |

### 3.3 用户侧形态（草案，实现时再锁文档）

```x
let t = typeof(x);
let n = size_of::<i32>();
let a = align_of::<Point>();
let o = offset_of::<Point, x>();
let name = type_name::<i32>();   // 静态类型名，多用于调试
let name2 = type_name(x);        // 与 typeof(x) 对应的名称
```

泛型中同样可用（语义上对类型参数查询）。

## 4. 哪些适合全局内置，哪些进 core / std？

### 4.1 筛选原则

1. 使用频率高，且与**语言本身**（类型、布局、安全控制流）强相关。  
2. 语义上编译期或零成本，或必须由语言特殊对待。  
3. freestanding 环境也合理需要。  
4. 放进库会显得别扭（例如「不可达」影响程序逻辑契约）。  

**宁缺毋滥。**

### 4.2 建议进语言全局（最终态清单）

| 名称 | 角色 |
|------|------|
| `typeof` | 编译期类型 |
| `type_name` | 编译期类型名（调试 / 诊断） |
| `size_of` | 大小 |
| `align_of` | 对齐 |
| `offset_of` | 字段偏移 |
| `unreachable` | 不可达（优化与安全契约） |
| `transmute` | 比特级类型转换（**unsafe** 语义） |
| `panic` | 恐慌 / 中止（语言核心失败语义） |

### 4.3 建议不进语言全局（库权威）

| 名称 | 归属 | 理由 |
|------|------|------|
| `assert` / `debug_assert` | core.debug | 常用，但是库契约；失败处理可配置 |
| 全局 `length(x)` | **不要**与 `x.length` 并列成两套正式 API | 长度统一为成员 `.length` |
| `print` / `println` | std.fmt | 绑定输入输出；freestanding 不能假定标准输出 |
| `minimum` / `maximum` / `absolute` | core 或数值类型方法 | 可库可方法；不必占全局名 |
| 字符串 / 切片业务操作 | 类型方法或 std | 见 §5、§6 |
| IO、网络、文件、集合、正则、序列化、日志 | std | 业务能力 |

### 4.4 概念区分（仍不谈实现）

| 概念 | 含义 |
|------|------|
| **语言内置** | 写源码即可用，语义由语言规定 |
| **库（需 import）** | 模块提供；可按需链接 |
| **可选「默认可见库」** | 若将来有 prelude，也应可关闭；**print 不要默认全局可见** |

## 5. 字符串、数组 / 切片：推荐属性与方法

### 5.1 切片 `T[]` 与固定数组 `T[N]`

| 成员 | 形态 | 说明 |
|------|------|------|
| `.length` | **属性** | 元素个数；固定数组可为编译期常量语义 |
| `.is_empty()` | 方法 | 等价于长度为 0 |
| `.first()` / `.last()` | 方法 | 建议可失败或不存在时明确语义（如 Option） |
| `.get(index)` | 方法 | 安全下标；失败语义明确 |
| `a[index]` | 下标运算 | 已有语言能力；与 `.get` 分工：下标可保留检查 / 恐慌策略，`.get` 偏可恢复失败 |

### 5.2 字符串相关（库类型目标面；语言级 string 后可对齐）

**视图（只读、不拥有缓冲）— 如 StrView**

| 成员 | 形态 | 说明 |
|------|------|------|
| `.length` | 属性 | 字节长度（若日后区分字符长度，须另名，如 `char_count`，禁止模糊） |
| `.is_empty()` | 方法 | |
| `.subview(offset, length)` | 方法 | 零拷贝子视图；越界语义明确 |
| `.substring(start, end)` | 方法 | 与 subview 二选一或严格定义区间约定，**禁止两套含糊重叠** |
| `.starts_with` / `.ends_with` / `.contains` | 方法 | 高频查询 |
| `.equal` / `.compare` | 方法 | 相等与序 |
| 查找类 | 方法 | 按需扩展，不进最小集也可 |

**拥有缓冲 — 如 String（含有界 capacity）**

| 成员 | 形态 | 说明 |
|------|------|------|
| `.length` | 属性 | 当前长度 |
| `.capacity` | 属性 | 可写容量（有界类型必有） |
| `.is_empty()` | 方法 | |
| 转为 / 作为视图 | 方法 | 只读观察底层字节 |
| 拼接 / `replace` 等 | 方法 | **标明**：可能失败（容量）或分配；文档禁止当零成本 |
| `+` | 运算符（后期可选） | 与显式 concat 同语义契约，不能更「静默」 |

**最小集（第一批体验）**：`.length`、`.is_empty`、子视图、`starts_with` / `ends_with` / `contains`、相等比较；`replace` / 拼接进第二批并写清成本。

**更晚**（不进最小体验面）：短字符串优化、字符串驻留——只影响性能策略，不改变上表用户可见最小集。

### 5.3 今日文档与库的对齐提示（仅事实，不定实现）

- 语言文档：切片可有 `.length` 一类成员。  
- `std.string` 已有 `String` / `StrView` 与一批函数式 API；**产品目标成员名用全称 `length` 等**。  
- 语言级 `string` 类型本身仍自举后引入。

## 6. 还有哪些类型值得加属性 / 方法？

按使用频率与可读性收益排序（只定「值得有」，不定实现顺序工程细节）。

### 6.1 优先（核心体验）

| 类型 | 推荐成员（示例） |
|------|------------------|
| 切片 / 固定数组 | §5.1 |
| `String` / `StrView`（及日后语言 string） | §5.2 |
| `Option` | `.is_some()`、`.is_none()`、`.unwrap()`、`.unwrap_or()`、`.map()` 等 |
| `Result` | `.is_ok()`、`.is_err()`、`.unwrap()`、`.unwrap_or()`、`.map()`、`.map_err()` 等 |

### 6.2 其次（常用且收益明显）

| 类型 | 推荐成员（示例） |
|------|------------------|
| 整数族 | `.absolute()`、包装运算、位计数类（名称全称、语义写清溢出） |
| 浮点 | `.absolute()`、`.floor()`、`.ceil()`、`.round()`、`.is_nan()` 等 |
| 指针 `*T` | `.is_null()`；偏移 / 读写等必须带 **unsafe** 语义 |
| 范围 Range（若语言或库提供） | `.start`、`.end`、`.contains()`、`.is_empty()` |

### 6.3 标准库类型（模块内方法面，不进语言全局）

| 类型 | 示例 |
|------|------|
| 动态数组 Vec | `.length`、`.capacity`、`.push()`、`.pop()`、`.is_empty()` |
| 映射 / 集合 | `.length`、`.get()`、`.insert()`、`.remove()`、`.contains_key()` 等 |
| 路径 / 文件 / 时长 | 各自领域高频操作 |

### 6.4 不建议硬凑

- 很少用的类型为对称而堆方法。  
- 把大分配、IO 藏进看似便宜的链式调用且文档不写成本。  
- 同一能力多个正式短名 / 全名并存。

## 8. 已拍板决策汇总

1. **类型上的属性与方法**：要；用户可按「类型自带能力」理解；语义是静态成员，不是动态挂表。  
2. **`length` 等**：属性优先；产品名全称。  
3. **子串**：优先视图语义；替换 / 拼接标明成本与失败。  
4. **`typeof` / `type_name` / `size_of` / `align_of` / `offset_of`**：适合语言全局、编译期语义。  
5. **print 与业务 API**：不进语言全局。  
6. **长度不要**再做全局 `length(x)` 与 `.length` 双正式 API。  
7. **优先类型面**：切片、字符串视图 / 拥有串、Option、Result；其次数值、指针、Range；再 std 容器。  
8. **语言级 string 类型**：自举后；方法清单可先按库类型定。
