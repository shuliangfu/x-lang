### 3.1 set abort 134／string exit=3＝import 共发射 struct 布局三面漂移（✅ 根因闭＠`5dc783d96`；残面见下）

**根因（已根修）**：`pipeline_backend_asm_codegen_ast_to_elf_c` 对每个发射模块（含 dep 自身）调 `typeck_merge_dep_struct_layouts_into_entry`；dep 自发射时 m==dm → merge 先 `reset_slot` 清零 dep 自身布局再从已清零槽「拷贝」→ dep 布局 ftr/offset 全被抹 0；entry merge 随后拷走全 0 → 三面（let-init 打包／FIELD 读＝结构体大小盲默认／dep 写＝0）各说各话。根修＝merge dep 循环跳过 `dm == mod`（typeck.x＋typeck_gen seed 同 commit）。验＝三面探针全绿＋24B 按值 `key%cap` 对＋`std.set` 不再 abort＋`std.string` exit 3→4＋双端 bitops OK＋L2 5/5。

**残面（另立卡）**：① ~~dep 内 `*s` DEREF 按值拷贝 CG002~~ **✅ 已闭＠`9b1d575c7`**（`pipeline_asm_push_sysv_memory_by_value_elf_c`／AAPCS64 孪生补 `ko==52`，G.7 复用 `lvalue_eff_addr` DEREF 面；run-set 门禁全绿）；② mac 对 /tmp scratch 点分 dep 不共发射（UN `_core_*`，既有缺口、dead_strip 产品面不挡）；③ u64 宽 INT_LIT 作 dep 调用实参到 0；④ std.string `compare_append_find` exit=4（run-string 残项）。

- **最小复现**（Ubuntu tip `8101be829`）：`core.m6/mod.x` 导出 `struct S6 { keys: *i32, cap: i32, length: i32 }`＋`setcap_readback(s: *S6, c: i32)`＋`readcap(s: *S6)`；main 侧 `let s: S6 = {…}` → `m.setcap_readback(&s, 8)` → 读 `s.cap`。
- **三面 by_name 全 miss＋各自盲默认**（objdump 实证，全 i32 三字段 `S9 {aa,bb,cc}` 即可复现）：main 匿名 STRUCT_LIT let-init 用自身打包计算（0/4/8，i32 时恰正确）；main VAR FIELD 读回退到**结构体总大小**偏移（3×i32 → 0xC，任何字段都读 size 处）；dep 内字段写回退**偏移 0**（写 aa 砸首字段）。dep 内自洽（写读同 0），跨面即错。指针字段时 init 打包也错（*i32 按 4B）。
- **set 链路**：`set.insert` → `slot(*s, key)` 按值拷贝布局垃圾 → `key % s.cap` cap=0 → mod 零 panic「panic: 0」→ abort 134。`with_capacity` 声称成功但主模块读 `s.cap`=0。
- **string exit=3**：`string.length(s)`（String 按值）同族。
- **定位层**：三面（let-init／FIELD 读／dep 写）的 by_name 链在 asm `-o` 共发射下对 import struct 全 miss：dep 模块布局表 parse-only 预跑不填（offset 只由 typeck `pipeline_module_struct_layout_set_field*` 填）；entry 侧 `typeck_merge_dep_struct_layouts_into_entry`（`runtime_pipeline_abi.x:4429`，`all_seeded==0` 分支）理论应同步＋合并，但 FIELD 读仍落盲默认（疑 merge 未及或 entry 侧 lit 布局遮蔽）。修法＝回到布局产生层（dep 预跑后同步 `glue_sync_struct_layout_field_offsets_c`＋merge 一次收三面），禁止再在消费点打第三个补丁。
- **无关已修面**：同模块 local struct 绿；dep 内指针写读自洽；heap alloc 绿。

### 3.2 建图：string append SEGV＝dep VAR 无 block_ref → 参数类型回填断链（2026-09-08 诊断，未动手）

- **链路（gdb 实证）**：`s.length`（`s: *String` 参数）FIELD 读发 **64 位 load**（`mov (%rax),%rax`）→ i32 值带相邻 padding 垃圾进 `s + length` 地址算术 → SEGV。
- **逐层根因**：`pipeline_expr_field_access_load_byte_sz` 路径 1（typeck 盖章）dep 无；路径 2（base 布局匹配）需 base VAR resolved 类型——`glue_fill_var_types_from_params_for_func`（emit 期 per-module 已跑、W live）靠 `pipeline_expr_block_ref_at` 向上爬 owner 块，但 **dep VAR expr 的 block_ref==0**（parser 不盖、typeck 才盖；入口模块走路径 1 不需要）→ 爬链断 → base 0 → 默认 8B。
- **试过并回退**：load_byte_sz 路径 2 补 TYPE_PTR 剥壳（.x＋seed）＝无效（base_tr 本来就 0，剥壳够不着）；无独立验证不提交。
- **✅ block_ref 半环已闭＠`b86679ad9`**：rest 航道 walker `glue_fill_var_block_refs_c` 上链（ASSIGN 28-38 家族也走 binop left/right 槽）；gdb 证 VAR 盖章✓、emit 期 base resolved＝param 类型（*S）✓。
- **✅ 全链闭＠`16745b87e`**：剥壳上链后 run-string 门禁绿。**航道谜底**：`load_byte_sz` 的链上胜者＝`pipeline_abi_field_load_sz_thin.x` 注入切片（inject first-wins T，盖过 mega `.x` 弱版）——mega `.x` 单独改永不上链；剥壳须改切片（权威）＋mega 孪生＋seed 冷孪生三处同 commit。同理可推 `_rec` 等其它 inject 切片（`binop_block_peel`／`assign_thin` 等）也有各自的 first-wins 权威。
