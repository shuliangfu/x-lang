## 0. 一分钟必读（做错了全盘作废）

| # | 铁律 | 违反后的后果 |
|---|------|----------------|
| 1 | **工程轨绿 ≠ 产品轨绿** | 假「可自举」→ 下一波雪崩（14→15 号真例） |
| 2 | **只认本 SHA 链出的 `compiler/xlang_asm`** | 旧 `xlang_asm` / `xlang_asm_stage1` / 残留 `xlang_asm2` 全是假绿 |
| 3 | **谈自举 / 结案 / 放行 = L4 真冷 + 全量 bstrict** | 只删相关 `.o` 的 L2 **不能**写「真冷全绿」 |
| 4 | **金标／真值 = Ubuntu x86_64**（日常 `ssh ubuntu-server`＝26.04） | 只 mac／只 Win 绿不得宣称产品放行；mac/Win **不能**取代 Ubuntu 金标 |
| 4b | **日常放行硬闸＝三端 L2**（macOS＋`ubuntu-server`＋`windows-server`，**同 tip**） | 任一端红 → **先修**，禁止写「本 tip 放行」；Win 底座未通前见 §8.4 过渡口径 |
| 5 | **mac→客机只 `git push` + 对端 `git pull`** | **禁止** scp／rsync **源码**当同步（日志／证据可 scp） |
| 6 | **`git commit` 只在 macOS** | Ubuntu / Windows 上禁止 commit；客机只 pull |
| 7 | **禁止 `cmd \| head` 当成功** | 必须看 **exit 码** + 运行结果 |
| 8 | **禁止 BEST_EFFORT / soft-skip 当绿** | `XLANG_W3_BSTRICT_BEST_EFFORT` 等只作调试，**不能写进放行** |
| 9 | **自举期不跑 `xlang check` 闸门**（L2/L4 均非强制；2026-08-05） | 禁止 Agent 默认塞 check；禁止因未 check 拒收矩阵/bstrict 绿 |

**口诀**：

```text
每步日常放行 = 三端同 tip 的 L2（macOS + ubuntu-server + windows-server；不跑 check；不默认 bstrict）
结案 / 谈自举 = 三端同 tip 的 L4 真冷（全擦 .o + 重链 + 矩阵；Ubuntu 侧另加全量 bstrict 为金标真值）
金标真值 = Ubuntu；mac／Win 是必须通过的端，但不能取代 Ubuntu 金标
源码同步 = 只 Mac commit/push；客机只 git pull；禁 scp 源码；禁默认升钉／默 bstrict
```

## 2. 两条轨道（永远分清）

| 轨道 | 测什么 | 典型命令 / 绿点 | 能否单独说「可自举」 |
|------|--------|-----------------|----------------------|
| **工程轨** | hybrid surface、seed 冷启动、Stage2 子集 | `prove_module_selfhost` IDENTICAL、R2 H=0、return-value=42、`bootstrap-verify` | **否** |
| **产品轨** | 本波 `xlang_asm` 编 **用户/测试程序** | 产品矩阵（§4）+ **`tests/run-all-bstrict.sh` exit 0** | **必要** |

- 工程轨可以写进度 KPI。  
- **产品轨红时禁止**写「可自举 / 本 SHA 放行 / 真冷全绿」。  
- Stage2 / `xlang_asm2` 是 freestanding 子集，**禁止**冒充产品 bstrict 主机。

## 3. 构建级别 L0～L4（写进汇报，缺则作废）

| 级 | 含义 | 能否当放行 |
|----|------|------------|
| **L0** | 旧 `xlang_asm` / `xlang_asm_stage1` / 未 pull 二进制 | **禁止** |
| **L1** | 热 g05 relink，不删 `.o` | **禁止**当矩阵/结案 |
| **L2** | 只 `rm` **相关** `.o` → make/g05 | **日常放行硬闸（须三端同 tip）**；**不能**写真冷 |
| **L3** | `bootstrap-driver-seed` + g05（std/core 可能残留旧 `.o`） | 开发端到端；谈自举前升 **L4** |
| **L4 真冷** | **全擦** `compiler|std|core` 下**全部** `*.o` + 删产品二进制 → pin seed → bootstrap → g05 → 矩阵 → bstrict | **结案 / 谈自举 / 三端放行默认标准** |

### 3.1 为何必须全擦（L4）

| 残留 | 会藏什么 |
|------|----------|
| 旧 `runtime_*_glue.o` / OS glue | ensure 从未跑；全擦后才 UNDEF |
| 旧 `std/**/*.o` / `core/**/*.o` | 链接语义与本 SHA 生成 C 不一致 |
| 旧 `parser_x.o` / `typeck_x.o` / `pipeline_x.o` | 前端债被旧目标盖住 |
| 旧 `xlang` / `xlang_asm` / `xlang-c` | 验的是上一 SHA（14 号假绿） |

**禁止**把「只删了 parser/codegen 再 g05」或「树里还有 100+ 旧 `.o`」叫做真冷测。

## 4. 日常真测（平时怎么测）

> **何时用**：每个微 commit、单点探针、「继续下一步」日常债。  
> **级别**：L2（日常放行硬闸）或 L3（开发端到端）。  
> **日常放行（2026-09-22）**：**三端同 tip L2**（macOS＋`ubuntu-server`＋`windows-server`）；**不跑 check**；**不默认**全量 bstrict／升钉。  
> **禁止写**：「真冷全绿」「可自举」「本 tip 放行」（缺任一端 L2 绿，或 tip 不一致）。  
> **过渡**：Win 底座 bootstrap／g05 未通前，见 §8.4；不得用「Win 暂跳过」冒充三端绿。

### 4.0 check（语法 + typeck · **自举期暂停闸门** · 2026-08-05）

> **用户修订（2026-08-04）**：曾「不在每次 L2 前跑 check；L4 再跑」。  
> **用户修订（2026-08-05）**：**暂时取消全部 check 语法检测闸门**——L2 **与** L4 **均不跑** `xlang check`。  
> 原因：check 债（parser 缺口 / 关键字名 / recovery 误报 / UX）与产品 emit 主链纠缠，修好又易回归，**严重拖慢自举**。  
> **自举完成（或用户明确重开）后再系统处理**（见 `语言语义诊断与LSP跟踪能力分析.md` 决策）。  
> 命令仍可用；**仅当用户明确要求**修 check / dogfood 时才跑。  
> skill 权威：`xlang-selfhost-product-gate` §3.3.0。

```bash
# 自举期默认不要跑。仅用户明确要求时：
# cd /path/to/xlang && ./compiler/xlang check [paths…]
```

| 场景 | 是否跑 check | 结果动作 |
|------|--------------|----------|
| **日常 L2/L3** | **否** | 直接 §4.1 探针/矩阵 |
| **L4 真冷 / 谈自举 / 日终兜底** | **否**（暂停） | 矩阵 + bstrict 验收即可宣称 L4 绿 |
| 用户明确要求修/跑 check | 是 | 不替代矩阵/bstrict；不因 check 红打断自举主链（除非用户要求先修） |

### 4.1 日常真测最小流程（三端同构；每端各跑一遍）

> **硬闸**：同一 `git rev-parse --short HEAD` 下，macOS、`ubuntu-server`、`windows-server` **都**要跑通本小节（或 §5 矩阵入口）。任一红先修。  
> **入口推荐**：`bash compiler/scripts/product_l2_matrix.sh`（或 `./xbuild` 文档化的 L2 别名）。Win 须在 Git Bash + w64devkit PATH 下。

```bash

git rev-parse --short HEAD

# --- 0. 自举期不跑 check（2026-08-05）---

# --- A. 只动了相关产物：L2 ---
# 例：改了 runtime_link_abi.from_x.c
cd compiler
# 按改动删相关 .o（示例，按实际文件改）
rm -f runtime_link_abi.o
# 若动 seed 产品面：
# cp -f seeds/codegen_gen.linux.x86_64.c codegen_gen.c
# cp -f seeds/parser_gen.linux.x86_64.c parser_gen.c
```

## 5. 产品矩阵（动产品面必跑）

> 在仓库根执行。`XLANG` 必须指向本波 `xlang_asm`。  
> **禁止** `cmd | head` 判成功；**必须**打印 build/run exit。  
> **G.7 单权威（wave299）**：`./xbuild l2-matrix` → `compiler/scripts/product_l2_matrix.sh`。  
> **根因**：`return 42` / option `102` 是**成功退出码**；在 `set -e` 下手写 `/tmp/rv` 会截断后续探针（历史假事故「矩阵被 rv=42 打断」）。权威脚本捕获 rc、跑全矩阵再汇总。

```bash
cd /path/to/xlang
export XLANG=./compiler/xlang_asm
test -x "$XLANG"
echo "SHA=$(git rev-parse --short HEAD) XLANG_mtime=$(stat -f '%Sm' -t '%Y-%m-%d %H:%M' "$XLANG" 2>/dev/null || stat -c '%y' "$XLANG")"

# 日常 L2 产品矩阵（唯一推荐入口）
./xbuild l2-matrix
# 期望：exit 0 · 末行 product_l2_matrix OK rv42／opt102／hello0／si0／f32
# 覆盖：return-value=42 · option=102 · stdlib-import=0 · hello=0+Hello · f32_f64=0

# 等价：
# bash compiler/scripts/product_l2_matrix.sh

# L4 真冷全测（wave341 · G.7 单权威；整波/结案/谈自举）
# ./xbuild l4
# 体 = compiler/scripts/product_l4_true_cold.sh
# 全擦 .o + seed pin + bootstrap-driver-seed + g05 + l2-matrix + bstrict
# （SKIP_BUILD=1；不跑 xlang check）
# 选项：./xbuild l4 --no-bstrict | --rebuild-only
```

可选 `-E` 抽检（非默认；矩阵绿后按需）：

```bash
$XLANG -E examples/hello.x > /tmp/he.c 2> /tmp/he.err
echo he:$?; wc -c /tmp/he.c   # 不能 0
grep -nE 'std_fmt_print\(|print_u8_ptr|Context _rc = 0|out->data|extern ssize_t write\(' /tmp/he.c | head || true
```

### 5.1 矩阵红灯（任一项 = 本波失败）

| 现象 | 含义 |
|------|------|
| `rv_run != 42` | 主机挂了，先修再谈一切 |
| option / si / hello **build ≠ 0** | 用户 import 路径红 |
| `pipeline error[XP003]`、`-E` 0 字节 | typeck/pipeline 硬失败，禁止当 soft |
| 生成 C：`struct … = 0` / 值类型 `out->` / bare `extern write` | codegen/stdlib/ABI 红 |
| 依赖 BEST_EFFORT / 旧 stage1 才绿 | **假绿** |
| 只改 `.x` 未改产品 seed（或反之）却说已修 | **双权威假绿** |

### 5.2 邻域矩阵（按债裁剪，防修坏别处）

| 改动类型 | 至少再绿 |
|----------|----------|
| overload / typeck 评分 | `tests/types/overload.x`、atomic 多宽整数、既有 PTR 重载（如 sort） |
| parser / unsafe region | 既有 unsafe 赋值探针 |
| codegen emit / init_globals | rv=42、option、hello；无「坏函数 let 升 top-level」 |
| link_abi / std.o 入链 | pure 不拖未用 heavy std；相关模块 wipe/ensure 探针 |
| SHARED ABI / mangle | **mac + Ubuntu** 都要矩阵（mac `-dead_strip` 会藏 UNDEF） |

## 6. 全量 bstrict（产品闸门套件）

约 **125** 个白名单脚本（含 `run-void-main-gate` + `run-comment-prefix`；历史钉盘日志可能仍写 123）。成功日志须类似：

```text
run-all-bstrict OK (125 scripts, …)
```

且 **进程 exit 0**。

### 6.1 正确跑法（验**已冷出/已 g05 的**产品二进制）

```bash
cd /path/to/xlang
# 确认无假绿 env（调试 env 不得用于放行）
env | grep -E 'BEST_EFFORT|SKIP_BUILD|VIS=|W3_BSTRICT' || true

# 关键：先用本波 L4/L3 产出 xlang_asm，再：
# SKIP_BUILD=1 → 只 cp xlang_asm → xlang，避免 bstrict 默认 bootstrap 盖掉刚冷出的二进制
# 默认会 cp 产品 xlang_asm（不是 Stage2 的 xlang_asm2）
export XLANG=./compiler/xlang_asm
XLANG_BSTRICT_SKIP_BUILD=1 bash tests/run-all-bstrict.sh 2>&1 \
  | tee /tmp/bstrict_$(uname -s)_$(git rev-parse --short HEAD).log
echo bstrict_exit:$?
tail -20 /tmp/bstrict_$(uname -s)_$(git rev-parse --short HEAD).log
```

### 6.2 关键禁止

| 禁止 | 原因 |
|------|------|
| 不设 `XLANG_BSTRICT_SKIP_BUILD` 却以为在验「刚 L4 的 xlang_asm」 | 脚本可能 `bootstrap-driver-bstrict` **重编盖掉** |
| `XLANG_BSTRICT_USE_ASM2=1` 当产品放行 | Stage2 freestanding 冒充产品 → SEGV/假红/假绿 |
| `XLANG_W3_BSTRICT_BEST_EFFORT=1` 当绿 | soft continue，**不是**严格闸门 |
| 日志是**别的 SHA** 的 tail | 只认 **本 SHA** 文件名与 `git rev-parse` 一致 |

### 6.3 全量 bstrict 何时必须跑

| 场景 | 是否必须 |
|------|----------|
| 日常微 commit L2 探针 | **否**（过重）；矩阵够即可 |
| 一波整体功能收口 | **是**（配 L4） |
| 改 glue / link ensure / seed pin / SHARED ABI | **是**（本波即可，可不等「叙事整波」） |
| 谈自举 / 升 tip L4 钉盘 / 三端结案 | **是 + 三端**（Ubuntu bstrict 金标） |

## 7. L4 真冷全测（怎么测「真冷」）

> **定义**：`remaining_o=0` 起编 + 本波重链 `xlang`/`xlang_asm`/`xlang-c` + §5 矩阵 + §6 全量 bstrict（**不含**强制 check，2026-08-05）。  
> **不是**：只 `rm` 相关 `.o`、只 bootstrap 不擦 std、不跑 bstrict。

### 8.0 硬口径（2026-09-22）

### 8.1 标准顺序（推荐）

```text
1. mac：改代码 → 本机 L2（矩阵／探针）

3. ubuntu-server：git pull --ff-only → 同 tip L2（日常）或 L4（结案）

```

### 8.2 三端最低对照表

### 8.4 Windows 底座（过渡状态 · 2026-09-22）
