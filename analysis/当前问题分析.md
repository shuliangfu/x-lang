## 2. 根因地图（已验证）

### 2.1 链式阻塞（更新）

```
[已修] import.Enum 变体 typeck 失败（parser.x #178 lexer_token_run_len）
    → import_binding_resolve 只查 func/const，不查 dep enum 类型名
    → token.TokenKind.TOKEN_* = unknown field
    ↓
[已修] parser.x typeck 推进到 #185；跨模块 struct 字段仍有债（见 §5）
    ↓
[已修] parser_gen pin 无 rew_line：lparen rewind 用 ( 的 line/col + 后移 pos → desync
    ↓
[已修] sticky L009 真因：lparen rewind 探针可落到块注释内部
      （例：`(void)x` 前注释里的 `cvtss2sd` → 数字 2 + 字母 s）
      → lexer_note_invalid_type_suffix 置 sticky 并打印
      → 整文件 parse 被 gate 判死
    ↓
[现阻塞] typeck.x 已能 parse，typeck 在 #359 typeck_coerce_init_lit_to_decl 失败
    → -E-extern out_len=0 → typeck_gen 无法 force regen
    → wave1218 SOA 实现仍不能从 .x 重发射
```

### 2.2 L009 真因（wave1218 收口）

| 环节 | 说明 |
|------|------|
| 触发词法 | 完整数字后紧跟字母 → sticky L009（如 `cvtss2sd` 中途 `2s`） |
| 为何进注释 | `parser_rewind_lex_for_lparen_control_stmt` 对任意 `TOKEN_LPAREN`（含 `(void)`）向前探 2..128 字节 |
| 探针落地 | 可落到**上一块注释中部**；此时不在 skip_whitespace 的 comment 状态 |
| 行号 desync | 旧实现复用 `(` 的 line/col；现改为 `parser_lexer_line_col_at_pos` 绝对扫描 |
| sticky 泄漏 | 探针触发 L009 后若不 `lexer_invalid_type_suffix_reset()`，整次 parse 被 pending gate 杀掉 |

**最小复现（已验证）**：

```x
export function f(x: i32): i32 {
  /* ... cvtss2sd ... */
  (void)x;   // LPAREN 触发 rewind 探入注释
  return x;
}
```

### 2.3 parser.x typeck #178（已修根）

- **不是** `lexer_token_run_len` 函数体写错  
- **是** `token.TokenKind.TOKEN_*` 跨模块 enum 类型跳未解析  
- 修复：`pipeline_typeck_field_import_binding_resolve_c` 增加 dep **enum 类型名** → `TYPE_NAMED`  
- 单测：`color.Color.RED` / `token.TokenKind.TOKEN_RETURN` 现 typeck OK  

### 2.4 跨模块 struct 字段（仍债）

`p.x` where `p: pt.Point`（import）仍 `unknown field`。  
`layout_deps` 代码存在，但产品路径未对用户 import 绿。  
→ 阻塞 `parser.x` 全绿 typeck / 全量 `-E-extern` regen（函数体内大量 `r.tok.line`）。
