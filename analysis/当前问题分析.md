## 1. 根因（纠正 wave1241 文档中的误判）

### 1.1 旧误判（已证伪）

「session 结束不 free dep arena → 252 文件累加」——**不成立作为峰值主因**：

- 产品链 stepped `.x`：`driver_parsed_work_cleanup` 对每个 dep 调 `ast_pool_*_release` + `free`（`n_deps` 在 cleanup 时正确）。
- 证据：目录峰值 ≈ `pipeline.x` 单文件峰值，而不是「小文件 × N」。

### 1.2 真正根因（三层）

1. **check 仍做完整 dep parse + entry typeck**（跳过 codegen，但**不是**「只扫语法」）。  
   `pipeline.x` import `parser` / `typeck` / `codegen` / `asm.backend` → 传递闭包是整个前端 mega 源。

2. **肥 AST 节点**：`struct ast_Expr` 内嵌多个 `name[128]`，单节点 ~**700B+**。  
   例：codegen dep 可达 **~1.2M exprs** → body 池 alone ~**800MB+**。

3. **macOS 大块 `malloc/free` 高水位**：顺序 parse 各 dep 时，`free` 后页常不归还 OS，峰值叠成 **sum(各 dep 解析峰)** 而非 **max**。  
   Ubuntu nostdlib 大块已有 mmap 路径（wave1241），但 GrowVec 默认仍走堆。

### 1.3 check 调用链（简）

```
xlang check <path>
  → driver_run_compiler_full（check_only=1）
    → driver_run_compiler_parsed
      → load_deps + prerun(parse_only for deps when check)
      → pipeline（typeck entry；check_only 跳过 codegen）
      → driver_parsed_work_cleanup（release sidecars + free）
```

## 2. wave1242 修复（权威）

| 改动 | 文件 | 作用 |
|------|------|------|
| **`ast_pool_drop_bodies_for_check`** | `compiler/ast_pool.c` | check 下 dep `parse_only` 成功后：丢掉 body GrowVec（exprs/blocks/…），**保留** types + Func 头 + layouts/imports；`body_ref=0` |
| **prerun 调用** | `compiler/src/runtime/rt_run_compiler_parsed.x` | `check != 0` 且 parse_only 成功 → `ast_pool_drop_bodies_for_check(dar[j], dmod[j])` |
| **GrowVec ≥1MiB 走 mmap** | `compiler/ast_pool.c` | 大块 `mmap(MAP_ANON)`；`grow_vec_free` → `munmap`，**立即还 RSS**（SHARED：mac + Linux） |
| **mmap 路径几何扩容（wave1242b）** | `compiler/ast_pool.c` `grow_vec_ensure` | 修 wave1242 回归：mmap 不能 in-place grow，线性 +4096 导致 **O(n²) memcpy**，`check main.x` 卡死式 100% CPU；改为 **double** 容量 |

`XLANG_DEBUG_CHECK_MEM=1` 可打印每次 drop 的 n_expr / freed_approx / live_expr_cap。

### 2.1 为何不在 `driver_dep_seeded_clear_all` 里 free

wave1241 已证：全局 typeck 槽仍引用 dep 指针时 free → SIGTRAP。  
**权威释放点**仍是 session 末 `driver_parsed_work_cleanup`；check 额外在 **prerun 后立刻丢 body**，降低**会话内峰值**。

### 2.2 剩余合理水位

- **入口文件自身** typeck 仍要完整 body AST（如 `check codegen.x` ~1.7GB）——中长期才应用 **string intern / 瘦 Expr**。  
- 目标「单 session <500MB」对 mega 入口尚未达标；**目录 check 已从 4.9GB → 1.8GB**，与最大单文件对齐。
