| Commit | 一句话 | 根修要点 |

| `775804765` | **formal_bare → product** 映射；**永不 rename `*_c`** | C 实现面 `log_write_c` 等保持 bare；product bare 走 map |
| `d79a368b2` | **rename `io_err_*` 产品面**（不是 io driver） | 允许 `io_err_*` → `std_error_io_err_*`；与 `io_*` driver 分离 |

### 3.1 formal_mod 契约（实现纪律）

1. **Per-symbol rename**：只改本 leaf 需要的 product bare；禁止「整表一刀切」打坏旁路。  
2. **`*_c` 永不 rename / 不 static-wrap**：encoding / log 等 C 实现面保持与 seed/host 一致。  
3. **Foreign co-emit 本地化**：本 `.o` 里出现的「别人家」`std_*`/`core_*` strong 要 localize，避免 Ubuntu multi-def。  
4. **formal_bare 表**：空名 / 宏面 / leaf clash 走显式 map（含 math bare、POSIX wait 等更早债的同族）。  
5. **`io_err_*` ≠ `io` driver**：error 模块产品面要 rename；io 模块 driver 符号规则另议，禁止混表。  
6. **PLATFORM: SHARED**：改 `xlang_compile_std_module.sh` 后 **Ubuntu 必 L4**；Mac 不能单独结案。

**L4 脚本内部顺序（勿拆成第二套菜谱）**：

1. 删除 `compiler/` `std/` `core/` 下**全部** `*.o`  
2. 删除本波须重链的产品二进制（`xlang` / `xlang_asm` / `xlang-c` / `bootstrap_xlangc` 等）  
3. `remaining_o == 0`  
4. pin linux.x86_64 seed gens → host-local `*_gen.c`  
5. `bootstrap-driver-seed`  
6. g05 prepare + relink → 本波 `xlang_asm`  
7. L2 产品矩阵（`product_l2_matrix.sh`）  
8. `XLANG_BSTRICT_SKIP_BUILD=1` 全量 `run-all-bstrict`  
9. **不跑** `xlang check`

### 5.4 formal_mod 符号面抽检（可选 · 出问题再跑）

在 **ensure 过** 对应 `.o` 之后：

```bash
# Linux：product 面应有 std_*；*_c 应仍为 *_c（未被改成 std_*_c 乱名）
nm -g std/error/error.o 2>/dev/null | rg 'io_err|std_error' | head -40
nm -g std/log/log.o 2>/dev/null | rg 'log_write|std_log' | head -40

# 不应再出现「foreign core_mem 多份 global strong」导致的 link multi-def
# （以 bstrict/run-set 为准；nm 仅辅助）
```

期望直觉：

- `io_err_*` 产品面 → 可见 `std_error_io_err_*`（或 rename 后的 product 名）  
- `*_c` 实现面 → **保持** `*_c`，不被 formal rename 吃掉  
- 无整文件级 blind redefine 把旁路 `std_*` 打成 multi-def

### 5.5 推荐复测矩阵（给 Trae）

| 场景 | 命令 | 期望 | 时长量级 |
|------|------|------|----------|
| **A. Ubuntu 金标 full L4** | `ssh …` → `git pull` → `./xbuild l4` | exit 0 + 尾标 OK | ~10–20 min（参考 11m41s） |
| **B. macOS 同 SHA L4**（SHARED） | 本机 tip=`d79a368b2` → `./xbuild l4` | 同上 | 可很长（参考曾 ~3h） |
| C. 仅矩阵 | `./xbuild l4 --no-bstrict` | `pass=5 fail=0` | 短于 full |

**不要**默认跑 check；**不要**并行叠多个 L4（防磁盘/锁互踩）。

### 5.6 失败时怎么报（给 Trae）

1. 贴 `git rev-parse HEAD` + `git log -1 --oneline`  
2. 贴日志路径 + 最后 50 行  
3. 贴**第一条**真实 `error:` / `UNDEF` / `multiple definition` / `cc failed`（不要只贴 step 名）  
4. 说明是否 full L4 还是 `--no-bstrict`  
5. **不要**改测试期望或 soft-skip 后报绿
