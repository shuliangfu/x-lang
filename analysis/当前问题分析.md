## 2. 本案问题地图：L8b 航道非确定性（g15 表 24 vs 28）✅ 已闭＠`51327d07b`

### 2.1 现象

- Ubuntu `run-compress` 门禁红：UNDEF `std_compress_{gzip,brotli,zstd}_stream_state_bytes`＋`brotli_stream_init_decompress_`。
- gdb 实证：链上 `labi_od_simple_group_sym_count(15)` 返回 **24**；而源码（`labi_ondemand_list.x:376`＋seed `:196`）**皆 28**。
- **同一配方两种结果**：晨间（08:54–09:09）全擦→`bootstrap-driver-seed`→`FORCE all` 产出**工作表**（bstrict 129/129 零红）；午后两次独立重建（`ensure FORCE`＋完整 L4 配方）均产出 **24 表**。
- macOS 不受影响（run-compress 全绿）。

### 2.2 数据流（谁产生、谁存储、谁消费）

- **产生**：`labi_prefer_try_x_to_o src/runtime/labi_ondemand_list.x`（ensure_host_cc_seed_o.sh:1546）——先 `pure_asm_x_to_o`（`./xlang -backend asm -c`），失败再 `-E`+cc。
- **存储**：mktemp 切片 `/tmp/labi_l8b.XXXXXX` → `pure_ld_partial_merge`（cc -r `--allow-multiple-definition`，**first-wins**）合入 `src/runtime_link_abi.o`。
- **消费**：`labi_od_user_needs_simple_group(user_o, 15)` 逐针查 UNDEF → 命中才走 sg15 ensure＋推送（compress.o／zlib.o／gzip.o＋系统 `.so`）。

### 2.3 已排除（证据）

| 源码漂移 | `grep return 28` 双孪生实证；git 处于 `41dd4e630`（含 `d583f61f5`） |

### 2.4 疑点（按序查）

1. **pure-asm thin 子集发射**：独立 `./xlang -backend asm -c list.x` 产物的 sym_count 体内只见 `0x19/0xc/0x0` 等非源码值——**过滤子集**（非全量发射）；其 g15 分支可能整段缺失→合并后 24 来自哪片？
2. **切片胜者漂移**：`labi_l8b` mktemp 内容依 pure-asm 成败而二态（thin 子集 vs full-seed `from_x.c`）；`pure_ld_partial_merge` first-wins，若某轮混入陈旧切片即胜者错。
3. **`/tmp` 陈旧切片污染**：`labi_l8b.*` mktemp 不自清理；午后多次 `git stash`／`git checkout` 窗口可能产出过 24 表切片并滞留 `/tmp`（晨间 L4 前无此窗口）。

### 2.5 结案

1. **产生**：`labi_od_simple_group_sym_count(g==15)` 双权威——`.x` 28／seed 24。L8c heavy.x prefer 常败（fn#142 typeck）→ ensure 丢 `.x` 切片、cc 编译 **full-seed** first-wins。
2. **假绿陷阱**：`grep return 28` 命中 seed **g==9**（slice，:196），不是 g15。Ubuntu objdump 实证 `cmpl $0xf` 后 `mov $0x18`＝gcc 栈帧＝seed 胜者。
3. **不是** `/tmp` 切片污染（mktemp 用后即 `rm -f`；不 glob）。
4. **修**：seed count 24→28（`e6c8d28f2`）；针触发后 c_face 补 4 T＋`.so` 挪回 compress 伴块（`51327d07b`）。**heavy.x 不动**。
5. **验**：双端 L2 5/5＋run-compress 绿；Ubuntu 链上 `mov $0x1c`。随后 Ubuntu L4 绿＠`074544410`。

## 2b. Darwin fmt 收集 FMT001 ✅ 已闭＠`e194cd294`

- **产生**：Darwin Cap `xlang_dir_open` 用 `SYS_open(O_RDONLY)`，无 `O_DIRECTORY`。Linux 同函数已传 `O_DIRECTORY`，libc `opendir(file)` 亦为 NULL。
- **存储**：heap DIR*（calloc + fd）；文件 open 成功 → 非空句柄。
- **消费**：`fmt_path_stat_kind` 以 opendir 成功当「是目录」→ `collect_paths_from_arg` walk 文件 fd → 空表 → FMT001「no .x files」。
- **钉盘蛋对照**：2026-09-02 pin egg 仍走 libc `opendir`（文件=NULL）；tip 冷链走 Darwin Cap。
- **假绿**：晨间 `d583f61f5` Darwin L4 日志仅 1KB＝`bstrict | tail -3`，管道 rc 跟 tail。
- **修**：G.7 补全 `xlang_dir_cap.h` Darwin `xlang_dir_open` 为 `O_RDONLY|O_DIRECTORY`（0x00100000）。不改 `fmt_path_stat_kind`／fmt-wrap。
- **验**：host-cc 文件=NULL／dir 可读；dir-cap Darwin gate；`xlang_asm fmt /tmp/*.x`；fmt-wrap 5/5；L2 5/5；双端 L4 129/129。

## 6. 结案（cmp 宽度 · `65d32efb5`）

**已闭。** 「u64 宽 INT_LIT 作 dep 调用实参到 0」旧卡**翻案**：实参两侧 `movabs $0x8000000000000000` 位级正确；真凶＝被调方 dep 泛型车道里 `t == 0` 的 EQ 比较被 32 位化（`cmp %eax,%ebx`＋`sete`）——`pipeline_asm_emit_cmp_elf` 的 `is_cmp_64bit` 只认 typeck stamp（dep 无 stamp→0）。根修＝左右操作数 stamp 空且为 VAR 时接 `glue_var_expr_type_ref_with_decl_fallback_c`（param 表／scope 走链，与 binop-shift 宽度同纪律），.x＋seed 冷孪生同 commit。验收：dep `eq64lit`/`clz64(2^63)=0`/use2 clz 矩阵全绿＋双端 L2 5/5＋mac 十门禁绿。§2 L8b 卡独立另收。
