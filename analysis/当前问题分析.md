## 1. 本波已修根因（按数据流）

### 1.1 target_cpu hybrid 符号缺失（原 g05 阻塞）

- **产生点**：`seeds/target_cpu_pure.from_x.c` 在 `XLANG_L2_TARGET_CPU_FLAGS_FROM_X` 下误剥全部业务函数  
- **修法**：仅剥 flags.x 的 5 函数；`tcp_eq5/6` 独立 `#ifndef`；删孤立 `#else`  
- **权威**：seed C；`target_cpu_flags.x` 不动  

### 1.2 Type 布局双权威撕裂（option/struct/type 根因）

- **产生点**：`seeds/parser_asm/parser_asm_type_ref_slice.inc` 本地 `struct ast_Type { name[64] }` vs arena `name[128]`  
- **症状**：by-value get/set 撕裂 → return type `expected ?`  
- **修法**：inc 对齐 `name[128]` / `region_label[128]`  

### 1.3 var_name_into 128 写 64 栈缓冲（field access SIGABRT）

- **产生点**：`pipeline_expr_var_name_into` `memset(out,0,128)` + field_access 栈 `uint8_t[64]`  
- **修法**：field_access / 相关 into 缓冲统一 128  

### 1.4 长标识符调用点截断

- **产生点**：`parser_asm_primary_slice.inc` `copy_ident` `len>63→63`；parser/typeck 多处 `>63`/`ni<64`  
- **修法**：拷贝/门控升至 127；func name write/equal 127  

### 1.5 void main 原型 vs 定义（hello BLD001）

- **产生点**：Type VOID 修好后，extern 原型仍 `void main`，定义 `int32_t main`  
- **修法**：codegen 原型路径对 `main`+VOID 同定义路径发 `int32_t`
