### 2.2 Ubuntu ELF SIGSEGV 根因 + 修复（commit `541a1d551`）

**现象**：`build -o` SIGSEGV 139；栈 `try_inline_struct_lit_return_call_to_slot_elf` → `glue_call_lookup_callee_mod_fi_arena` → `glue_module_func_index_by_name` → `pipeline_module_num_funcs`；module=`0xf7ef9950`。

**gdb 证据**（option.none_i32）：

```text
LOOKUP  ctx.module_ref@16 = 0x7ffff7ef9950   ← 合法指针
BAD_MOD                    0xf7ef9950        ← 高 32 位被清掉
name = "none_i32"
```

**产生点**：x86_64 ELF enc `arch_x86_64_enc_enc_or_rbx_rax` 发 `orl %ebx,%eax`（`09 D8`）。`g02f_load_ptr_at` 按 usize `| (byte << n)` 拼 64 位指针；**SHL 已是 64 位**（`shl %cl,%rax`），**OR 是 32 位**，每次 OR 把 EAX 零扩展、高 32 清零。ARM64 ELF seed 早已是 `orr x0,x0,x1`（64 位）→ macOS 不崩。

**修**：`orq`/`andq`/`xorq`（REX.W `48 09 D8` / `48 21 D8` / `48 31 D8`）。权威：

- `compiler/src/asm/backend_x86_64_enc_c.x`（产品 prefer）
- `compiler/src/asm/arch/x86_64_enc.x`
- `compiler/seeds/backend_x86_64_enc_c.from_x.c` + surface

同 commit 同语义。**禁止**在 `pipeline_module_num_funcs` 加判空糊绿。

**验证节奏（Ubuntu 金标 · 2-pass，非 L4）**：

1. 重编 `backend_x86_64_enc_c.o` + `link-product-asm`（编码器字面量 `48 09 d8` 入链）
2. 删 `backend_try_inline_dispatch.o` + 再 relink（**新 xlang** 纯 asm 重编 `g02f_load_ptr_at` → `or %rax,mem` 64 位）
3. L2 5/5；fao build+run=0；htr build+run=0

L4 单 pass 仍会用 pin 蛋编 try_inline（旧 `orl`）。谈自举 / 升钉时 L4 后须再 heat 一次 try_inline，或接受「L4 后再 `rm try_inline.o && link-product-asm`」。

## 3. 当前非主刀 / 下一刀候选

### 3.1 cookbook `http_chunked_decode` — **已闭（本波）**

**现象**：formal_mod cc `std/http/mod.x` → incomplete `struct core_result_` → http.o 未入链 UNDEF `std_http_*` → cookbook BLD001。Clang 文案是 incomplete type；GCC 可能写成 no member `value`。

**产生**：host-C `emit_expr` STRUCT_LIT。`core.result` 的 `ok`／`err` 写匿名 `{ value: x, … }`。入口模块 typeck 会 backfill `struct_lit_struct_name`；作为 **dep 共发射**（http `-o` C）时名字仍空，只发当前模块前缀 → `(struct core_result_){ .value = … }`。函数签名走 `emit_type` Result_* 改写，已是完整 `struct core_result_Result_i32`。

**存储**：`codegen.x` STRUCT_LIT 发射 + `seeds/codegen_gen.linux.x86_64.c` twin。

**消费**：`xlang_compile_std_module.sh` host-cc；随后 ld。

**修**：G.7 补既有 STRUCT_LIT——空名从 `resolved_type_ref`／当前函数返回 TYPE_NAMED 恢复，再走 skip_abi_dup。禁 shell `#define`／改 std。双端 heat codegen 后：L2 5/5；`http_chunked_decode`／`http_parse_status` 0。

### 3.2 cookbook `cli_subcommand` — **parse P001 已闭（本波）**；`-o` UNDEF 另叶

**现象**：`-E` `parse error[P001]: no functions`；`-o` 缺 `_main`。

**产生**：`parse_body_lets_into` 绑定名只收 IDENT(59)／SELF(51)／UNDERSCORE(52)。cookbook `let run: u8[3] = [114,117,110]` 的 `run` 是 TOKEN_RUN（一元 `run <expr>`，lexer `ident_len=0`）→ `return false` 整函数软丢掉。`run[0]` 与 `run <expr>` 同 token 流，**不能**把 RUN 收成 IDENT。

**存储**：产品 pin `parser_gen.linux.x86_64.c` + twin `parser.x`；诊断权威 `parser_asm_body_tl_slice.inc`（P010–P013 族）。

**消费**：`parse_into_buf` → num_funcs=0 → P001／ld 缺 `_main`。

**修**：G.7 补既有 IDENT|SELF 闸门——非法关键字硬 **P014**（sticky，与 P011/P013 同）；**不**把 `run` 当变量。cookbook 改为 `let cmd`（字节仍是 `"run"`）。同模式：param 表／top-level let／buf onefunc。禁改 std／禁第二套名字解析。

**证（双端 L2）**：`let run`／`function f(run: i32)` → P014；`let cmd`／`let self` 绿；cli `-E` num_funcs=1；双端 L2 5/5；http cookbook 仍 0。

**本叶不搅**：`-o` 仍 UNDEF `std_cli_err_*`／`std_cli_parse_from_iter`——`xlang_compile_std_module.sh` 无 `std/cli` 条目（仅 `xlang_compile_std_x.sh` 编裸 `cli.x`，无 `std_cli_` 前缀）。那是 formal_mod／labi 独立债。

### 3.3 cookbook `csv_write_row` — **T001 已闭（本波）**；parse_row 7 参 SIGSEGV 另叶

**现象**：`csv.write_row` → T001 `no impl for type with method write_row`。

**产生**：`import("std.csv")` 方法表只看 `mod.x` export。`write_row`／`parse_row` 实现在 `csv.x`（`csv_write_row_c`／`csv_parse_row_c` + leaf 薄包装），门面没有。typeck 当 method_call → LANG-004。

**存储**：`std/csv/mod.x` 门面；`--bare-impl` `csv.x` 裸 `_c`；labi simple g==4／fk0 k==5 精确 UNDEF 探针。

**消费**：typeck T001；补门面后 Darwin ld-only 若探针无 `std_csv_write_row` 则不拉 `csv.o`。

**修**：G.7 补既有门面（tar／base64 `extern *_c` + `_rc`／unsafe 薄包装）+ 补全 labi csv 针表（count 3→5／fk0 2→4）。禁复制算法、禁改 typeck 去合并 csv.x export（会与 `next_field` 双份爆炸）。

**证（mac L2）**：T001 消失；`csv.o` 含 `_std_csv_write_row`／`_std_csv_parse_row`；`write_row` 单路径 run=0；`tests/csv/main.x` 0；L2 5/5。

**本叶不搅**：cookbook 全路径仍 SIGSEGV 139——`parse_row` 7 参 import METHOD_CALL 把第 7 参存 `[sp]`，callee 读 `x6`（`out_count=0x63`）。同模块 7 参 CALL 绿。那是 `pipeline_asm_emit_method_call_elf_c` AAPCS64 独立债。
