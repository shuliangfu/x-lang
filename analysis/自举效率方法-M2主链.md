# 自举效率方法：M2 主链（M1 工具 · M3 收口）

> **日期**：2026-09-16  
> **决策**：主攻 **M2**（纯 asm / CG002 / mega FORCE）。**M1** 只做 M2 需要的语言/codegen 刀。**M3** 放最后。  
> **枝**：`dev` · 钉盘仍 **`ecdb5cc1e`**（升钉默认不做）  
> **交叉**：终局债 [`C迁移追踪.md`](C迁移追踪.md) · 仪表盘 [`自举进度.md`](自举进度.md) · RFC [`7.2.1-parser-inc-port-ABI-RFC.md`](7.2.1-parser-inc-port-ABI-RFC.md)

日常波次流水仍只写 `自举进度.md` §6。本文是**方法决策**，不是 tip 日记。

---

## 0. 一句话

dest-buffer 工厂（9 月 10–16 日一天 20–44 波）已到**局部最优**。再切 header 不推进阶段 13。  
终局函数是 **host `cc` → 0**，不是「C 算法搬进 `.x`」。对准该函数的主刀是 **M2**。

---

## 1. 效率函数（必须先改对）

| 旧工厂最大化 | 终局要最大化 |
|--------------|--------------|
| 每波一个 compositor dest-buffer | 编译器 TU 不再被 host `cc` 编 |
| 独立 `FROM_X` 门 + C trampoline 持 `name[256]` | asm backend 直接出 `.o` |
| 双端 L2 不红 | 冷启动不 `execve(cc)`（阶段 12–13） |

分清两个「无 C」，禁止混谈：

1. **手写 C = 0**：权威在 `.x`，host 仍可 `cc` `-E` 产物。dest-buffer 服务这个。  
2. **host-cc = 0**（阶段 12–13 宣布自举）：永不 `execve(cc)`。dest-buffer 几乎不碰这个。

typeck 墙（mega `-E`）已关。再为 (1) 加班是爬错的山。

---

## 2. 为何现行 dest-buffer 不再高效

9 月工厂当时正确：无 struct 按值、无 `local u8[N]`、RFC Route B 被认为太大，于是 B-minus + trampoline。

边际收益已掉到接近 0：

- P6h 切完 header，body 仍 C；产品 hello 不走 buf 路径  
- 每波仍 `cc` trampoline；pthin 常因 CG002 走 `-E`+`cc`  
- 剩下没切的全是工厂绕开的墙（栈数组、嵌套 `while`、`STRING_LIT≤64`、P3f、glue_tail、mega assemble）

**继续绕墙切小片 = 用最高熟练度打最低杠杆。**

---

## 3. 三方法

### M1 — 语言墙打包 + parser 整块迁

解开 trampoline 的根：函数内 `u8[N]`/`i32[N]`、嵌套 `while`+`break` 不再 parse-drop、`STRING_LIT` 放宽或诊断走表。  
RFC Route B 的缩小版。单独做完：parser 可删 C 孪生，**产品仍 `cc` mega / pin**。

### M2 — 纯 asm / CG002 / mega FORCE（主刀）

山在：

- `runtime_pipeline_abi.x` 98k（`-E` typeck 已过；assemble / CG002 / 产品 FORCE 未开）  
- `runtime_pipeline_abi.from_x.c` 68k 仍可能 host-cc  
- pthin 多条 lane 因 CG002 / weak polish 走 `-E`+`cc`  
- 前端 `.x` 已在（typeck 25k / codegen 27k），产品仍 pin-first  

CG002 常是缺一类 emit（局部数组、label、按值返回、嵌套控制流），与 M1 的墙同一座山。  
**不打穿 M2，M1 迁再干净也还是 hybrid `cc`，M3 也无法零 cc。**

### M3 — 二进制 stage0 收口

stage0 = 现有双端 pin 蛋（已存在），不是手写最小 asm seed。  
源全 `.x` → stage0 `-backend asm` → stage1 → 再编自己 → v2==v3 → 删 C seed / 删 `labi_invoke_cc`。  
**依赖 M2。** 现在开 M3 = 验的仍是 C 链。

---

## 4. 决策（已拍板）

**主攻 M2。M1 是 M2 的工具，不是并列主战场。M3 是 M2 打穿后的收口。**

单独比效率：**M2 > M1 > M3**（M3 不能先开，故排第三）。

落地序：

```text
M2：CG002 分类 + 小 pthin 纯 asm 站住（不再回落 -E+cc）
        │
        ├─ 缺栈数组 / 嵌套循环 / 某 emit → 插一刀薄 M1，立刻回到 M2
        │
        ▼
M2：mega FORCE，替换 from_x.c（产品 .o 是 asm）
        │
        ▼
M3：pin 蛋当 stage0，产品禁 labi_invoke_cc，v2==v3
        │
        ▼
parser 残体按文件整迁（那时的 M1 收尾）→ 删 C 孪生
```

禁止：

- 再开「一 helper 一波」dest-buffer 当主刀  
- 完整 M1（glue_tail / `parse_type_ref` / `append_byte` 整块迁）抢在 CG002 分类之前  
- 无视分类产品 FORCE 整 mega  
- 先手写最小 asm seed（pin 蛋已能当 stage0）  
- Windows / MSVC / NT 进金标终局  
- 注释-only 波；eq / 覆盖戏

以前工厂时代的禁令（P3f dest-buffer `parse_type_ref`、`append_byte`、glue_tail、mega FORCE）**不是终局护栏**。在语言墙 / emit 类未开时硬开仍会红；分类证明需要时再开，且须根修产生点。

## 5. 本波起怎么干（M2 第一步）

1. **分类 CG002**（最小复现，按 emit 类记账，禁止对着 2554 函数盲 FORCE）

3. mega 仍 **禁产品默认 FORCE**，直到该类在小文件上复现绿  

验证：日常 **L2**（Darwin + Ubuntu）；不跑 `xlang check`；L4 仅整波 / 谈自举。  
SHARED 改动双端。Windows：`ssh windows-server` 对齐 SHA，不跑本地 xlang。
