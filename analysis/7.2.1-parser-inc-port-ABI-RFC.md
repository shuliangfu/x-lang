# 7.2.1 主债务 — `.inc` C parser 逻辑移植 `.x` 的 ABI 路线 RFC

> **状态**：草案待决（2026-09-10 · 由 7.2.1 主债务两轮深查催生）
> **对象**：`compiler/seeds/parser_asm/` 35 个 `*.inc` 切片（73,854 行 C parser 函数体）＋主文件 `parser_asm_thin_c.from_x.c` 4,555 行壳
> **前置建图**：[C迁移追踪.md](C迁移追踪.md) 7.2.1 条（精确建图＋二次深查＋ABI 障碍首查）
> **约束**：hybrid 壳层（P1–P20 守卫＋seed TU＋`ld -r`）已全部就位，移植后无需改 g05 流；不破坏 G05 51 objs；**ABI 路线未决前禁开首域**（本文件即闸门）。

---

## 1. 问题

`.inc` 函数以 C 结构体**按值传参**（`struct parser_asm_token tok` / `struct parser_asm_lexer_result r`），`.x` 语言无此 C 结构体面。**任何**移植路径都必须先回答「这些按值参数在 `.x` 侧如何表达」——这是全链 ABI 变更，thin `.x` 委托与冷 C 双面须同步。

**量化**：helpers 切片单文件 14 处按值传参；4+ 切片文件涉及；35 切片总计 2,341 个符号。

---

## 2. 候选路线

### 路线 A — Opaque 指针化（`*u8` 透传）

**做法**：`.x` 侧签名全部改为 `*u8`（opaque），`.x` 函数体不消费结构体字段——把字段访问留在 C 薄面（每结构体一组 `get`/`set` 访问器或直接在 C 桥里预提取）。

| 维度 | 评估 |
|----|------|
| 语言面改动 | **零**（`.x` 已支持 `*u8`） |
| ABI 变更范围 | **窄**：调用方（thin `.x` 委托＋冷 C）签名同步改 `*u8` |
| 移植后 LOC | `.x` 侧多为转发＋访问器编排——**逻辑真体仍在 C 访问器**（若字段访问不搬） |
| 迁移纯度 | **低-中**：若 `.x` 只做转发，host-cc C 行数不减（与 hybrid 壳层等价）；若把字段访问也搬为 `.x` 逐字段读写，则逐域可行但代码量膨胀 |
| 风险 | 访问器膨胀；按值语义（copy 语义）须在 `.x` 手工复制 |

### 路线 B — `.x` struct 支持（新语言面）

**做法**：给 `.x` 语言加 C ABI 兼容的 struct 类型声明＋按值传参（或至少 `#[repr(C)]` 结构体），使 `.inc` 函数可近逐行移植。

| 维度 | 评估 |
|----|------|
| 语言面改动 | **大**：struct 声明／字段访问／按值传参／按值返回（后者 parser 面已见消费需求 `r.main_idx`） |
| ABI 变更范围 | **零**（签名原样）——移植后冷 C 与 `.x` 面直接可互换 |
| 移植后 LOC | **高纯度**：C 体近逐行搬，host-cc C 行数真减 |
| 风险 | 新语言面爆炸半径大（typeck／codegen／parser 三面）；struct-by-value 涉及 ABI 布局对齐；可能与 4.2.8 AST name slot 等 leave-off 交叠 |

### 路线 C — 混合（首域试点先行）

**做法**：不动语言面也不动 ABI——先挑一个**无按值传参**的切片域做真移植（验证刀法），同时把按值域标记为 blocked-on-ABI，待路线 A/B 决策后批量处理。

| 维度 | 评估 |
|----|------|
| 前置 | **零**——立即可开 |
| 收益 | 小（一个域 ≈1k 行） |
| 风险 | 低；但主力域（helpers／body_tl 等按值密集区）全部 blocked |

## 3. 量化对比

| 维度 | A opaque | B struct | C 试点 |
|----|----|----|----|
| 前置语言面改动 | 0 | 大 | 0 |
| ABI 变更 | 窄（签名改 `*u8`） | 0 | 0 |
| host-cc C 真减 | 低-中（取决于访问器深度） | **高** | 小 |
| 波次估算 | ~35 波（每切片 1 波）＋访问器波 | 语言面先行（数波）＋~35 波 | 1 波＋剩余 blocked |
| 爆炸半径 | thin 委托＋冷 C 双面 | 全编译器 | 单域 |

---

## 4. 建议（非决定）

**建议 C → B 序**：先开一个无按值切片域试点（立即可做、验证 `.x` 直写 parser 逻辑的刀法与 prove 面），同时把本 RFC 提交架构决策（路线 B 的语言面投入 vs 长期收益——若 parser 域 struct 按值密集，B 是唯一能同时达成「真减 host-cc C」与「签名不变」的路线）。**A 仅在 B 被否决时作为降级**（且须接受访问器膨胀或 C 行数不减的现实）。

## 5a. suite 切片深查（2026-09-10 追加）

**suite 结构量化**：28,517 行 / 1,989 函数，分两类：

| 类 | 函数数 | 行占比 | 特征 |
|---|---|---|---|
| **audit 探针** | 1,956（98%） | ~90% | 模板化（byte-compare 链＋lexer_next＋kind 判定），`lexer_result`/`lexer`/`slice_u8` 按值/指针 |
| **真逻辑** | 22 | ~10% | classify_toplevel（switch 链）、validate_toplevel、skip_allow_modifiers、balanced_*_probe、import_path_score、is_type_start 等 |

**按值类型集中度**（2,755 实例的 90%+）：
- `struct parser_asm_lexer` = **3 标量**（pos/line/col，16B）——1,800 处
- `struct parser_asm_slice_u8` = **2 标量**（data/length，16B）——669 处

**B-minus 路线（新提案）**：不添 `.x` struct 语言面，而是**标量分解**——这两个微结构体在 ABI 边界拆为独立标量参（`lexer`→`pos+line+col`，`slice_u8`→`data+length`），`.x` 函数用纯标量参数表达。98% audit 探针是高度模板化的 byte-compare 链——**适合生成器批量产 `.x`**（读 C 模板→产 `.x` 函数）。剩余 22 个真逻辑函数手工迁。**前置为零**（不改语言面），但 28k 行的量级仍是多波。

| 路线 | 前置 | 覆盖 | 估算波次 |
|---|---|---|---|
| C（纯标量域） | 0 | 仅 stretch lite（已完成） | ✅ 1 波 |
| **B-minus（标量分解）** | **0（不改语言）** | lexer/slice_u8 域（~90% 按值） | ~40-60 波（生成器可缩至 ~10） |
| B（struct 语言面） | 大 | 全部 | 语言面 3-5 波＋移植 40 波 |
| A（opaque 指针） | 0 | 全部（访问器膨胀） | 35 波＋访问器 |

## 5b. B-minus 具体化：lexer-step extern 最小桥（2026-09-10 追加）

**核心洞察**：suite 全部 1,956 个 audit 探针的 struct 依赖集中在一个原语——`lexer_next_into(&r, lex, source)` 调用（246 个独立调用点，每个函数 1-3 次），用于构造 `lexer_result`（嵌套 lexer + token）。若把这一步封装为**最小 extern 面**，则 .x 可承载全部审计逻辑。

**最小桥设计**（~80 行 C，一次性）：
```c
// 在 C 侧（一次性、不变）：
// 推进 lexer 一步并返回下一个 token kind
int32_t parser_asm_lex_step_kind_c(void *lex_inout, void *source);
// 读/写 lexer 的 pos/line/col（三个标量访问器）
size_t parser_asm_lex_pos_c(void *lex);
void parser_asm_lex_set_pos_c(void *lex, size_t pos);
// 读 token 的 ident_len / token_start
int32_t parser_asm_lex_tok_ident_len_c(void *lex);
size_t parser_asm_lex_tok_start_c(void *lex);
```

**效果**：`.x` 函数用 `*u8`（opaque lexer）+ `*u8`（source）+ 上述 extern 表达全部审计逻辑（byte-compare 链 + kind 判定 + 深度计数 + 循环）。**逻辑真体搬 `.x`**（host-cc C 真减），仅 lexer 步进和字段读留在 C（~80 行，不变）。

**本质**：这是 Route A（opaque）和 B（struct）之间的**最优折衷**——不添语言面，不减逻辑迁纯度，C 残留仅 ~80 行 lexer 步进桥。

**落地件**（本 commit）：
