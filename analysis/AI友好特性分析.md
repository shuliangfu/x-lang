## 0. 一句话结论

| 问题 | 答案 |
|------|------|
| AI 写 X 为什么容易错？ | 训练语料几乎没有 X；模型会用 **Rust / Go / C / Zig** 的语感硬套。 |
| 语言侧最该优化什么？ | **可预测、显式、少糖、一写法一事**；错误信息**可自动修复**；公开 API **意图可检索**。 |
| 工具侧最该优化什么？ | **小步生成 → 真编译器 check → 结构化诊断 → 最小 diff** 闭环（MCP/CLI/Skills）。 |
| 有没有银弹语法？ | **没有。** 任何「AI 专属语法」若与人读规范分叉，都会双权威并恶化准确率。 |
| 现在就改语言吗？ | **大面积不。** 自举完成前：强化 L0 文档/示例/禁区清单；工具与诊断可准备。语言面大改挂 **P1/P2a**。 |

**成功标准（可验收）**：

1. 在固定评测集上，主流 Agent **零示例 / 仅官方 Skill+MCP** 时，**首次 check 通过率**与 **3 轮内修通率** 相对基线明显上升。  
2. 高频幻觉类错误（`->`、`fn`、假 import、编造 std API、省略类型注解）有 **稳定诊断码 + 可行动建议**。  
3. 新人/Agent 不必背完整手册：靠 **cheat-sheet + MCP Resources + 可编译示例** 即可写 hello 级与小库级代码。  
4. 全链路 **单权威**：`docs/` + 编译器 +（从 G.9 生成的）doc；Skills/MCP **只引用不改写语法**。

## 1. 问题地图：AI 写代码在错什么

### 1.1 错误不是「模型笨」，是系统缺反馈

```text
训练先验（Rust/Go/C…）──► 生成 .x 候选
                              │
         ┌────────────────────┼────────────────────┐
         ▼                    ▼                    ▼
   语法/API 幻觉          语义/安全幻觉          风格/构建幻觉
   (fn, ->, crate)       (裸指针, 漏 unsafe)    (假 package, 乱目录)
         │                    │                    │
         └────────────────────┴────────────────────┘
                              │
                    缺：快且诚实的编译器闭环
                    缺：机器可读诊断 + explain
                    缺：短真源（而非 200 页手册）
                              │
                              ▼
                    多轮猜 → 准确率崩 / 假绿
```

AI 友好 = **降低先验冲突** + **加快纠错闭环** + **把意图写在接口上**。  
三者缺一，只堆「更聪明的模型」收益有限。

### 1.2 高频幻觉清单（X 特有 / 高发）

按「模型常写」→「X 真相」对照。Skills 的 `anti-patterns` 与诊断建议应**同源**此表。

| ID | 模型常写 | X 正确写法 | 伤害 | 缓解（语言 / 工具） |
|----|----------|------------|------|---------------------|
| H01 | `obj->field` | `obj.field`（指针也用 `.`） | 直接 parse/风格错 | 诊断「did you mean `.`？」；Skill 铁律 |
| H02 | `fn foo()` / `func` | `function foo(...): T` | 高 | 关键字错诊断 + cheat-sheet |
| H03 | `let x = 1` 无类型 | `let x: i32 = 1` | 产品路径硬失败 P010 | 保持**强制注解**（对 AI 是好事，见 §3.2） |
| H04 | `import foo` / `use` / `crate::` | `const m = import("std.io");` | 高 | 单一 import 形；诊断给模板 |
| H05 | `package` / `mod` 声明 | 目录 = 模块，`mod.x` | 中 | scaffold 官方布局 |
| H06 | `[]u8` / `&[u8]` / `String` 语言级 | `u8[]` / `*u8` + len / 库 `String` | 高 | 文档+std 查询；string 语言级后自举再谈 |
| H07 | `println!` / `fmt.Println` | `std.fmt` 等真实 API | 高 | MCP `std_lookup`；禁编造 |
| H08 | 省略 `export` 仍跨模块用 | strict 下须 `export` | 中 | 诊断 + 示例一律 export 公开 API |
| H09 | 安全上下文解引用裸指针 | `unsafe { ... }` | 安全 | 已有门禁；建议文案写清「包进 unsafe」 |
| H10 | Rust 生命周期 / `'a` | region / 库语义 | 中 | 勿在示例混 Rust 注释语法 |
| H11 | `async fn` 染色叙事过度 | 以现行 async 模型为准 | 中 | Skills 诚实；禁过度承诺 |
| H12 | 分号乱省 / 乱加 | 设计：仅 `}` 结尾可省；实现有 ASI 债 | 中 | 自举后收紧 ASI（见 LSP 分析 A） |
| H13 | 中文注释当正式 API 说明 | G.9：**英文** docblock | 中 | 对 Agent few-shot 与 `xlang doc` |
| H14 | 一次生成 200 行不 check | 小步 + 必验 | 极高 | Skill 强制；MCP 默认工作流 |
| H15 | 编造错误码 / 忽视 XP\*\*\* | `explain CODE` | 高 | 结构化 diag + 稳定 code |
| H16 | `dyn Trait` / `dyn Clone` | `let x: Clone = a`（写 trait 名） | 高 | 单路径 TYPE_DYN；P013 硬拒 `dyn` 前缀 |

### 1.3 三类失败模式

| 类型 | 表现 | 主要杠杆 |
|------|------|----------|
| **先验冲突** | 外文语法渗入 | 语法差异最小化（在合理范围内）+ 强禁区 + 诊断 |
| **知识空白** | 不知 std/模块/构建 | MCP Resources、示例、scaffold、doc |
| **闭环失败** | 能写不能修 | 诊断质量、check 速度、explain、测试入口 |

## 2. 「AI 友好语言」原则（针对 X 的设计准则）

下列原则用于**评审任何语言变更**：「这项改动是帮模型，还是只是人爽/糖？」

### 2.1 十条原则

| # | 原则 | 含义 | 反例（避免） |
|---|------|------|--------------|
| P1 | **显式优于聪明** | 类型、返回值、错误路径写在表面上 | 重度类型推断让模型猜错仍通过 |
| P2 | **一概念一写法** | 同一事只有一种惯用语法 | 三种 import、两种成员访问 |
| P3 | **局部可理解** | 看函数签名 + 附近 20 行能懂契约 | 依赖全文件宏/隐式上下文 |
| P4 | **稳定表面** | 关键字与诊断码少变 | 每年改名 `function`→`fn` |
| P5 | **可机械检查** | 意图能变成 check/合约 | 只写散文 README |
| P6 | **错误可行动** | 诊断含位置、code、建议补丁形态 | 「invalid expression」 |
| P7 | **短反馈环** | 单文件 check 秒级；增量友好 | 必须全仓 L4 才能发现笔误 |
| P8 | **示例即可编译** | 文档/Skill 示例必须当前 tip 可过 | 伪代码当规范 |
| P9 | **单权威** | docs = 编译器 = MCP 引用 | Skill 里手写第二套语法 |
| P10 | **人机同构** | 对人清晰的也对模型清晰；不为 AI 开旁路方言 | `ai_only` 语法糖 |

### 2.2 X 已具备的「先天友好」点（应保留并强化）

| 已有特性 | 为何帮 AI |
|----------|-----------|
| **强制类型注解**（`let` 须类型） | 减少「推断漂移」；模型生成形状更固定 |
| **字段只有 `.`** | 单一规则，记住即可 |
| **`function` / `struct` 关键字完整** | 比符号汤更易检索与对齐 |
| **绑定 import 一种形** | `const m = import("…")` 模板可抄 |
| **属性 `#[…]` 一族** | 与 cfg/no_mangle 一致，合约也可挂同一族 |
| **export 可见性** | 公开 API 边界清晰 |
| **unsafe 显式块** | 危险操作可 grep、可审 |
| **G.9 英文 JSDoc** | 给模型的高质量 few-shot / 将来 doc 真源 |
| **错误码体系**（P0xx / XP / L7…） | 可 `explain`、可统计幻觉类 |

### 2.3 当前「不友好」缺口（优化靶心）

| 缺口 | 影响 | 归属 |
|------|------|------|
| 训练语料近零 | 先验全靠外文 | 工具+示例+生态（无法靠改两行语法解决） |
| 语言级 string 体验弱 | 应用代码绕 `*u8`+len，模型易幻觉 String | 自举后类型（已有时机文） |
| check 闸门暂停 / 诊断半残 | 闭环弱 | 自举后 P2a |
| LSP 半实现 | IDE Agent 信息少 | 自举后 |
| MCP / 应用 Skills 未产品化 | 无「官方正确姿势」 | P1 起 |
| std API 可发现性 | 易编造函数名 | doc + MCP std_lookup + 模块索引 |
| 合约仅文档级 | 意图不执行 | 见合约文 L1/L2 |
| ASI / 分号实现与设计不完全一致 | 模型与文档打架 | 自举后收紧 |
| 示例/教程碎片 | few-shot 质量不稳 | P1 五分钟教程 + 可编译 examples |

## 3. 语言面优化：让「生成的代码形状」更稳

> 原则：**少发明新语法；优先消灭歧义与双写法；糖必须可逆推到核心形。**

### 3.1 语法表面：稳定模板（给模型的「标准形」）

官方应冻结一套 **Canonical X Shape**（Skill cheat-sheet 与 MCP overview 共用）：

```x
const io = import("std.io");
const fmt = import("std.fmt");

/**
 * Entry: print greeting and exit 0.
 * @return void — process success
 */
export function main(): void {
  fmt.println("Hello World");
}
```

```x
/**
 * Add two integers.
 * @param a i32 — left
 * @param b i32 — right
 * @return i32 — a + b
 */
export function add(a: i32, b: i32): i32 {
  return a + b;
}
```

```x
export struct Point {
  x: i32;
  y: i32;
}

export function origin(): Point {
  return Point { x: 0, y: 0 };
}
```

**纪律**：所有官方示例、scaffold、MCP prompts **只用这一族形状**；禁止示例里混 Rust/Go。

### 3.2 应该坚持的「对 AI 更严」规则

| 规则 | 为何更利于准确率 |
|------|------------------|
| **禁止默认类型推断**（现状倾向） | 模型输出自带类型 → 形状可验证、可 diff |
| **返回类型必写** | 签名即规格，利于 post 合约与生成体 |
| **公开 API 必须 `export` + G.9** | 接口可被检索与生成约束 |
| **源语言无 `->`** | 单一成员访问 |
| **错误用 Result/显式码，少 silent null** | 模型少「忘了处理」 |

**不要为了「像 Rust 所以模型会写」去改成 `fn`/`->`**：短期或许可抄外文，长期会毁掉「简单可学」与单权威；且混合语感会更乱。

### 3.3 建议的语言/诊断增强（按 ROI）

| ID | 增强 | 类型 | 时机 | 准确率机制 |
|----|------|------|------|------------|
| L-A | **幻觉友好诊断**：`fn`/`->`/`use`/`package` 给出「X 等价写法」 | 诊断 | 自举后尽早 | 一轮修对 |
| L-B | **import 修复建议**：错误路径 → 候选 `std.*` / 相对路径 | 诊断 | P2a | 少编造模块 |
| L-C | **未知标识符 + 相似 std 符号** | typeck+索引 | P2a | 少编造 API |
| L-D | **强制分号与文档一致**（收紧 ASI） | parser | 自举后专门窗口 | 人机/文档一致 |
| L-E | **unused / 重复定义**做满 | typeck | 自举后 | 减死代码幻觉 |
| L-F | **语言级 string / str**（库语义升语言体验） | 类型 | 自举后（已有文） | 应用代码降绕 |
| L-G | **轻量合约 L1→L2** | 库/语言 | 见合约文 | 先意图后实现 |
| L-H | **统一 `debug_assert` 真正可剥离** | core+cfg | P1–P2 | 检查与性能叙事清晰 |
| L-I | **禁止或警告「危险糖」**（若未来加宏） | 语言政策 | 长期 | 防不可局部理解 |
| L-J | **`xlang doc` 从 G.9 抽 API** | 工具+约定 | P2–P3 | 模型读同一真源 |

### 3.4 不建议的「伪 AI 友好」改动

| 想法 | 为何拒绝或慎用 |
|------|----------------|
| 为 AI 单独发明第二套语法 | 双权威；人读文档与模型输出分裂 |
| 全面类型推断「像 TS」 | 错误后移；模型假绿更重 |
| 自动插入 `unsafe` | 掩盖危险；安全审计失效 |
| 吞掉错误让编译「尽量过」 | 14 号假绿同类；教坏 Agent |
| 超强宏 / 隐式全局 | 局部不可理解；生成不可控 |
| 在未自举时上大泛型/string 语言级 | 爆炸半径 × residual |

## 4. 工具面优化：闭环比语法更重要

### 4.1 黄金闭环（所有 Agent 默认剧本）

```text
读真源（cheat-sheet / MCP Resource / 邻域示例）
    → 生成最小可编译切片（≤1 文件或 1 函数）
    → xlang check | MCP xlang_check
    → 若红：结构化 diag + explain CODE
    → 最小 diff 只改相关处
    → 再 check → 可选 fmt / build / test
    → 汇报：改动文件 + 命令结果（禁止「我觉得绿」）
```

**没有闭环的「更聪明生成」= 赌先验。**  
有闭环时，语言只需保证：**错误可定位、建议可执行、一次只暴露一个主因（或排序稳定）**。

### 4.2 工具能力优先级（面向准确率）

| 优先级 | 能力 | 作用 | 状态 |
|--------|------|------|------|
| **P0** | 结构化诊断（path, line, col, code, message, hint） | 自动修的前提 | 部分有；需冻结 schema |
| **P0** | 诚实 `check` / `build` exit 契约 | 防假绿 | check 闸门自举期暂停 |
| **P0** | 官方 Skill：syntax-guard + app-dev + fix-diag | 行为纠偏 | 分析有，产品待落地 |
| **P1** | `explain CODE` 机器可读 | 少瞎改 | CLI 有人读路径，需强化 |
| **P1** | MCP：overview / check / explain / std_lookup / scaffold | 不背手册 | 分析有 |
| **P1** | `fmt` 幂等 | 降噪声 diff | 体验打磨 |
| **P1** | `new`/`init` + 标准布局 | 禁 invent 构建 | 时序表 P1 |
| **P2** | LSP hover 签名 + references | 编辑器 Agent | 半实现 |
| **P2** | `xlang test` 统一入口 | 生成后验 | 设计文有 |
| **P2** | 合约检查接入 debug 构建 | 意图级失败 | 合约文 |
| **P3** | 评测集 + 回归「AI 准确率」 | 优化可量化 | 待建 |

细节 Tools 列表见 MCP 专文；Skills 列表见官方 Skills 专文——**本文不复制**（G.7 文档版）。

### 4.3 诊断「可自动修复」清单（设计目标）

每条诊断理想字段：

```text
code: P010
path: src/main.x
line/col: 12:7
message: let requires type annotation
hint: write `let name: i32 = 0;`
related: docs/06-变量与常量.md
fix_template: "let $name: $Type = $expr;"
```

| 错误类 | 建议 hint 形态 |
|--------|----------------|
| 缺类型 | 插入 `: Type` 模板 |
| `->` | 替换为 `.` |
| 未知 `fn` | 「用 function」 |
| 未 export | 「加 export 或改为模块内私有调用」 |
| 缺 unsafe | 「将解引用包在 unsafe { }」 |
| 未知 std 符号 | 列出同模块导出候选（top-k） |
| 合约失败（未来） | 指出 pre/post 哪条、实际值（debug） |

### 4.4 速度：Agent 会疯狂调用编译器

| 手段 | 说明 |
|------|------|
| 单文件 / 模块级 check | 不必每次全量 bstrict |
| 缓存 parse/typeck（增量） | 自举后编译优化轨（P2b） |
| MCP 短超时 + 清晰错误 | 避免 Agent 空转 |
| 禁止把 L4 全擦写进应用 Skill | 分轨（Skills 文已强调） |

## 5. 知识面优化：让模型「查得到正确答案」

### 5.1 真源分层（给 AI 的阅读预算）

| 层 | 体积 | 内容 | 谁维护 |
|----|------|------|--------|
| **L0 一页 cheat-sheet** | ~1–2 屏 | 关键字、import、let、function、`.`、unsafe、main | 从 docs **生成**或精摘 + 版本戳 |
| **L1 可编译示例集** | 20–50 个小文件 | hello、import、struct、错误处理、unsafe 边界 | `examples/` + CI 编译 |
| **L2 模块 API 卡** | 按模块 | 每个 export 的签名 + 一句用途（G.9/`xlang doc`） | std 作者强制 G.9 |
| **L3 完整 docs** | 全书 | 人读权威 | docs/ |
| **L4 analysis/** | 设计债 | **不要**当应用 Agent 默认输入 | 实现者用 |

Agent 默认只喂 **L0+L1+当前任务邻域**；需要 API 时查 L2（MCP）；争议以 L3 为准。

### 5.2 示例工程规范（直接提升 few-shot 质量）

| 规则 | 原因 |
|------|------|
| 示例必须 `xlang check`/`-o` 绿（CI） | 防教坏模型 |
| 公开函数带英文 G.9 | 与产品代码同构 |
| 文件头标注 `// PLATFORM:` 若相关 | 少跨平台幻觉 |
| 禁止半伪代码 | 「…」只允许在 analysis，不许在 examples |
| 每个幻觉 ID（H01…）至少 1 个 **正反例** | Skill anti-patterns 可链到文件 |

### 5.3 std 可发现性

| 措施 | 效果 |
|------|------|
| 稳定模块路径表（`std.io`、`std.fmt`…） | import 不猜 |
| MCP `std_lookup` / `std_index` Resource | 禁编造 API |
| 导出符号与文档同 commit | 防漂移 |
| 常用「任务 → 模块」索引（读文件、写、HTTP…） | 缩短搜索 |

### 5.4 文档与实现漂移治理

AI 对**过期文档**极度敏感（会坚定幻觉）。

| 机制 | 说明 |
|------|------|
| `docs/语法文档与实现对照.md` 持续更新 | 已有 |
| 发布/升钉时跑「示例全绿」 | P1 |
| MCP Resource 带 **compiler version / docs rev** | 过期可警告 |
| Skill 版本戳与 xlang 版本对齐 | Skills 文已要求 |

## 6. 合约与类型：从「看起来对」到「可检查对」

详见 [`合约设计与Agent支持.md`](./合约设计与Agent支持.md)。此处只钉 **AI 准确率视角**：

| 层 | 对 AI 的价值 |
|----|----------------|
| **类型 + export 签名** | 生成目标形状 |
| **G.9 L0** | 自然语言意图（参数/空指针/cap） |
| **L1 require / assert** | 实现后立刻可炸 |
| **L2 #[requires]/#[ensures]** | 「先写意图再填体」工业化 |
| **typeck 安全** | 内存类错误编译期拦，不靠模型自觉 |

推荐 Agent 顺序：**签名 → G.9 →（可选合约）→ 体 → check**。  
禁止：先喷 200 行体再补类型。

## 7. 评测：没有数字就没有「更友好」

### 7.1 建议建立 `tests/ai-friendliness/` 或外部 harness（自举后）

| 套件 | 内容 | 指标 |
|------|------|------|
| **语法迁移题** | 把 Rust/Go 片段改写成 X | 首次通过率 |
| **补全题** | 给签名+G.9，只生成函数体 | check 绿 / 合约绿 |
| **修错题** | 给含 H01–H15 的坏文件 | 3 轮内修通率 |
| **std 使用题** | 「读文件前 N 字节」等 | 是否调用真实 API |
| **脚手架题** | 空目录建 bin | 布局是否官方 |

### 7.2 基线协议（防自嗨）

1. 固定模型与温度（或固定 Agent 配置）。  
2. **仅**提供官方 Skill + MCP（或仅 cheat-sheet 对照组）。  
3. 禁止把标准答案放进上下文。  
4. 记录：轮次、diag code 分布、是否假绿。  
5. 语言/诊断变更后重跑，**回归**准确率。

### 7.3 与产品 bstrict 的关系

- **bstrict**：编译器/产品正确性。  
- **AI harness**：语言+工具对模型的可用性。  
二者正交；**不能**用 bstrict 绿宣称 AI 友好完成。

## 9. 与「人友好」是否冲突？

| 维度 | 结论 |
|------|------|
| 显式类型 | 对人稍繁、对 AI/维护更稳 → **坚持**（符合 X「清晰」） |
| 完整关键字 `function` | 对人略长、对检索友好 → **坚持** |
| 严格分号 | 对人需习惯、对工具一致 → **设计坚持，实现收齐** |
| 好诊断 | 人机双赢 |
| 少糖 | 人机双赢 |
| 复杂宏/隐式 | 人机双输 |

**结论**：X 的 AI 友好路径与「简单、清晰、安全」**同向**；冲突项应优先保全**可预测性**，而不是堆糖讨好外文模型。

## 14. 结语

让 AI **更准地写 X**，不是把 X 改成 Rust 的马甲，而是：

1. **表面可预测**：一写法、显式类型、完整关键字、单一成员访问；  
2. **意图可检查**：G.9 → 合约 → typeck 安全分层；  
3. **错误可闭环**：结构化诊断 + explain + 官方 Skill/MCP 强制「生成即验」；  
4. **知识可检索**：短 cheat-sheet、可编译示例、std 索引，全部与编译器同权威。

模型会继续带着外文先验；**X 的优势是用简单规则 + 诚实工具把错误打回并教它改对**。  
这条路径与「三高一低」一致，且应作为**自举完成后的一等产品目标**，用评测集说话，而不是用口号。
