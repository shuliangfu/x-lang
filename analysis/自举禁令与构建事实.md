# 自举禁令与构建事实

> 从 [自举进度.md](自举进度.md) 挪来（w1539 精简时整理），一条一句，删掉了过时条目。旧的整段禁令原文见提交 `2ca777577` 里的 `自举进度.md` 第 5 行。新禁令直接加在对应小节，不写进流水。

## 1. 全局禁令

- 不跑 g05_prepare、`build_xlang_asm.sh`、L4；不升钉，钉盘 `ecdb5cc1e`。
- 禁 bak 175735。
- 不用 CloudAgent，不默认 bstrict，不碰 glue_tail、pipeline_abi mega、P4b。
- 不改 `runtime_pipeline_abi.x` 和 pabi 种子，也不重编 pabi 去换结构体字面量。
- 不新增 host-cc 的 `.c`；新发现的 10.x 只记账，不插队。
- 改了源码必须重编相关 `.o` 和产品再跑 L2，不拿旧的 leftover 或 warm 产品冒充本刀已验。
- 旧波留下的 `xlang.prev`、`pabi_weak*.prev` 之类回滚副本一律不拷回产品。
- Windows 上无后缀的 `./xlang`、`xlang_asm`、`xlang-c` 必须是本波实际在跑的编译器。

## 2. 不许退回 host cc 的对象

- Darwin arm64 这些对象不要改回先走 host cc：random_fill、time_os、kv_mmap、string_fast、path_fast、sync_os、dynlib_os、net_workers、process_argv、queue_contention、env_os、log_os、compress_zlib、crypto、process_os、lock_diag、tls_mbedtls_bio、net_udp、net_addr_fast、net_sock_fast、net_ipv6_fast、net_io_batch_fast、panic、user_env、`std/runtime/runtime.o`、`core/slice/slice.o`、`runtime_sqlite_glue_stub.o`、`runtime_sqlite_glue.o`、`runtime_atomic_glue.o`、`runtime_dir_cap.o`、`runtime_process_import_alias.o`、`std/debug/debug.o`、`std/async/async.o`。
- Darwin 上这些别名、桥和桩不要用 host cc 编：`std/io/io.o`、`std/io/driver.o`、`std/compress/compress.o`、`src/lexer/lexer.o`、`build_tool_libc_bridge.o`、`build_tool_main.o`、`asm_xlang_lsp_diag_stub.o`、`src/lsp/lsp_diag_pipeline_sizes.o`、`typeck_lsp_io_stub.o`、`ast_asm_bare_link_alias.o`、`backend_asm_bare_link_alias.o`、`backend_asm_strict_fallback_alias.o`、`driver_compile_asm_link_alias.o`、`src/asm/pipeline_run_x_link_alias.o`、`pipeline_wpo_strict_link_alias.o`、`pipeline_wpo_typecheck_emit_bridge.o`、`pipeline_asm_run_all_alias.o`、`pipeline_asm_typecheck_alias.o`、`pipeline_glue_link.o`、`pipeline_run_impl_alias.o`、`pipeline_run_bootstrap_trampoline.o`、`pipeline_phase_parse_only_alias.o`、`cfg_eval_link_alias.o`、`runtime_asm_build.o`、`rt_stack.o`。
- 每个对象的钩子只认它自己那份，不要放宽去匹配别的对象；别名和桥只转发到已有符号，不在里面再写一套实现。
- 这些对象从 `.x` 纯 asm 只编一次，失败就停，不退回种子、不重试、不走 cc：`runtime_driver_strict_glue_stubs.o`、P9a 词法桥、主链 `parser_asm_parse_expr_link`，以及 binop、unary、as_suffix、ternary、primary 的赋值器和跳板。
- 这些种子只留在盘上，不删，也不再进产品链：`seeds/runtime_driver_strict_glue_stubs.from_x.c`、`seeds/parser_asm_lex_step_bridge.from_x.c`、`seeds/pthin_expr_binop.from_x.c`、`seeds/pthin_expr_unary.from_x.c`、`seeds/pthin_expr_as_suffix.from_x.c`、`seeds/pthin_expr_ternary.from_x.c`、`seeds/pthin_expr_primary.from_x.c`。
- w1531 删掉的十一份 `*_surface.from_x.c` 和 w1533 删掉的六份真种子不要加回来，旁路脚本也不要再 host-cc 它们。
- 主链 `parser_asm_parse_expr_link` 不加回 cc 兜底或十二次重试。

## 3. 代码生成不变量

- 大于 16 字节的拷贝门要含 EXPR_VAR（3）、FIELD（44）、STRUCT_LIT（45），不加 ARRAY_LIT（46）；字段赋值和下标赋值的拷贝种类也不加 46。
- 大于 16 字节的变量、字段、下标、字面量成员要整块拷贝，不改回只载一个 qword 或只存源地址，也不送进 16 字节成对存储或间接单 qword 存储。
- 9 到 16 字节的字段赋值、下标赋值、字面量成员要写满，不只写低 8 字节；9 到 16 字节的字段没有调用时也要 deref。
- 不超过 8 字节的非调用字段不改成只载一个 qword。
- 步进为 12 的元素和 12 字节的字面量成员不做 16 字节存储。
- `pipeline_asm_host_is_arm64_c` 不改回加载 BSS；`load_rbp_to_rdx` 在 ta 非 0 时不改成返回 0。
- 不清掉产品 TEXT 末尾的字段赋值洞，重链会丢掉它。
- 不为凑旧对象去掉 x19 或 rbx 那 16 字节，也不拿 clang 叶子或旧的 `0x858`／`0x860` 帧做前缀对照。
- 机器码不是链上对象前缀的纯 asm 不换进去；不替换 `typeck_c_module_stubs.o` 和 `pipeline_bootstrap_orchestration.o`。
- 不用 gcc `-E` 编 emit_one。

## 4. 词法桥、cfg_eval 和跳板

- 不拿掉词法桥函数里的垫块，也不收掉 Win64 按地址传 lexer 的包装。
- 不拿掉 g05 的 cfg_eval 阶梯，阶梯不退回 `-E`；不把 target_arch 或 not() 加回 `cfg_eval_host_lit.x`。
- 不把一元或 as_suffix 赋值器抄进 primary、ternary、ctrl、fn_block 等别的跳板，也不抄一份 ternary 赋值器。
- 不给 `pthin_expr_as_suffix.x` 加第 5 个 export，不给 `pthin_expr_ternary.x` 加函数或第 5 个 export。
- 这些薄层不要合成一份翻译单元：诊断、诊断后段、三元、simd、as 后缀、库函数扫描、import 收集、辅助函数、拉伸表、词法跳过、函数块、控制流。

## 5. 用现行编译器写 `.x` 的坑

- 栈帧盖不住最后一槽时要拆函数：一个函数里别放两次调用，补缓冲和解析目录项要分函数，u16 存储不要贴着栈帧边。
- 256、512、4096 字节的缓冲和 64 槽表不放在栈上。
- 文件级 let 不直接赋值（状态槽、计数槽、缓存槽、CPU 特性字、诊断码），也不把它的地址直接放进调用参数。
- 不用形参当下标读写，不用 `&ent[i]` 取值的地址；比较前先把两边字节各存进局部变量。
- 函数指针用 dlsym 取，不把函数名当指针传（signal、mbedtls_ssl_set_bio、sqlite 回调等）。
- 不调用 libc getenv、setenv、unsetenv，也不调用可变参数的 fcntl 或 syscall。
- libSystem 的下划线名在 `.x` 里要多写一个下划线，例如 `___atomic_load_4`、`___open`、`___getdirentries64`、`___exit`、`___fcntl`、`___error`。
- 10 个参数的函数先转发给不超过 8 个参数的函数；Darwin 上第 11 个 i32 参数偏移是 12，不是 16。
- 打包用左移 32 位，不乘 4294967296；不要用 packed 当局部变量名。
- 长度钳制放在返回 usize 的函数里，不放进同时构造两个切片字面量的函数，否则那次调用会被丢掉。
- `.x` 里定义 `entry` 会进入口模式只发出 entry，含 main 的翻译单元只发出 main，入口要单独合并。
- 路径拷贝循环和 512 字节栈缓冲不放进同一个翻译单元，ELF 诊断的循环和消息缓冲也一样；`rt_lib_root.x` 里只放一个 while。
- 带 `xlang_panic_` 未定义符号的 panic 包装对象不要交给 `pure_asm_x_to_o`，那个门会丢掉它。
- `net_tcp_errno_ptr`、`net_udp_errno_ptr`、`net_ipv6_errno_ptr` 已由 tcp、udp、ipv6 导出，别的对象不要再定义。
- 弱符号保持弱：`io_read_batch` 一族、七个词法桥、strict glue 弱桩、两个 getenv 符号都不改成强符号。

## 6. 构建脚本事实

- 权威拼法在 `g05_ensure_relink_prereqs.sh` 的 Class CB。`pthin-*-pure` 只在 Darwin arm64 走；Linux／Windows 保留第一遍 hybrid 结果。第一遍打出的临时对象随后会被删掉，日志里的「pure-asm」不会自动留在胶水里。
- 分段器份数写死在 `ensure_host_cc_seed_o.sh`（`len(starts)`／`len(orig)`），对不上直接退出；用 `len(starts)` 的门比函数个数多 1（末尾追加了文件长度）。不按 `export` 行数改门。simd 是 7 个函数分 5 段。
- 整包 P1–P20 合并已被 Class BX 关掉，`XLANG_G05_PTHIN_FULL=1` 会段错误。
- Darwin 产品链接是 `g05_relink_xlang.sh`，对象表在 `g05_relink_env.sh`（Darwin 分支把 `parser_asm_thin_glue.o` 放进 `_USER_ASM_LINK`）。`$CC -o xlang` 失败会删掉 `xlang`，重链前先备份 `xlang` 与 `xlang_asm`。
- `build_xlang_asm.sh` 的 `ensure_bstrict_seed_support_objs` 会在种子或 `.inc` 比胶水新时，用不带 `FROM_X` 的 host `cc` 盖掉 Class CB 胶水；`relink_xlang_asm_experimental_bootstrap.sh` 同样会盖胶水，且链的是 `build_asm/x_seed_bridge.o`。两条都不走。
- `XLANG_ASM_BSTRICT_RELINK_ONLY` 要求 `asm_backend_partial.o` 不小于 8192 字节，现在是 phase1 stub；设 `XLANG_ASM_BSTRICT_RELINK_ALLOW_PHASE1_STUB=1` 跳门后链接失败会删掉已有二进制。不要走。
- `build_xlang_asm.sh` 的 strict 重链在 Darwin 上已知失败，失败前可能已把产品换坏，「product untouched」提示不会拷回。
- 当前产品把 `.x` 里的 `va_start` 编成外部调用 `_va_start`，不是 builtin，所以 `diag_reportf`／`diag_vreportf` 等四条 va_list 仍留种子（终局待办 5.1、10.9）。
- `build_asm/seed_host/asm_backend_partial.o` 由 `g05_ensure_relink_prereqs.sh` 的 `g05_backend_partial_pure` 每代从 `src/asm/backend_seed_mega_fallback.x` 纯 asm 整对象编出（w1540），失败即停；`seeds/backend_seed_mega_fallback.from_x.c` 只留盘。
- 跳板种子 `seeds/pthin_*.from_x.c` 里，binop（w1535）、unary（w1536）、as_suffix（w1537）、ternary（w1538）、primary（w1539）的产品路径都不再 host cc，种子只留在盘上。ternary 没有单独赋值器。
