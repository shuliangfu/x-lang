# 7.2.1 P12g RFC — `skip_one_trait` 全迁 `.x`（ent 栈镜像 ABI）

> 2026-09-13 · Agent 起草（P19d 后第一份 mega 级规划；执行须用户点名批准）

## 1. 目标与现状

`parser_asm_skip_one_trait_into_slice_c`（`parser_asm_skip_tl_slice.inc` L5434–7605，**~1374 行真码**）是 7.2.1 残表中最大的单函数 host-cc 面。功能＝`trait Name[<T>] { methods }` 的 token 走查＋方法注册表（wave421–438 签名状态机）。

量化：17 处 `lexer_next_into`、**304 处 `ent->` 写**、309 处 `mi_reg` 引用、289 处 `method_ret_/method_param_` 状态族、签名状态机含 ret/param 两族 ×24 状态变量（run 2..160 多层回扫）。

## 2. 候选路线

### 路线 α — ent 栈镜像（推荐）

C trampoline 在栈上持有 `xlang_skip_trait_reg_ent_t ent`（memset 0），把 `&ent` 作 opaque `*u8` 传给 `.x`；`.x` 完整执行六段走查（header→method 发现→签名机→回扫→前扫→注册），所有 `ent->X` 写改为 `.x` 侧固定偏移写（偏移由 seed `_Static_assert` offsetof pin，单一布局权威）；成功（RBRACE 且 name_len>0）后 C 才把镜像 commit 进 `g_xlang_skip_trait_reg` 并 `reg_n++`——**与现 C 语义逐位等价**（失败路径镜像直接丢弃，与现「保留槽位不增计数」等价）。

- ✅ 一条 ABI 根墙（一个 opaque 指针＋P9a 桥既有面）；C trampoline 仅 ~30 行；`.x` 真减 1374 行 host-cc
- ✅ 无中间态：整函数一次切换（`#ifdef` gate），无「半机器在 C 半在 .x」的交叉态
- ⚠ `.x` 需在固定偏移写 i32/数组（P13c write_fields 惯例已有）；offsetof pin ~25 断言

### 路线 β — 分层 dest-buffer（P12c 式）

`.x` 只迁 header＋method 名发现（dest 128B name 缓冲），签名机留 C。**否决**：签名机＝函数体 ~70%，残留几乎不减；且 `.x`/C 交叉调用每方法两次，语义切割点在最复杂的状态机内部——中间态等价性不可证。

### 路线 γ — 回调 sink（C 注册 sink API）

`.x` 走查、C 提供 ~30 个 sink 函数。**否决**：新 C API 面＝第二走查路径（G.7 红线）。

## 3. 波次拆分（每波同语义）

P12g 是**一条 ABI 根墙**，但 1374 行一 commit 评审不可行。按「同一镜像 ABI、`.x` 内部分阶段生长、C 端一次切换」拆三波：

| 波 | 内容 | 切换点 |
|---|---|---|
| g-1 | `.x`：header 走查（trait/ident/`<...>`/for-type）＋ent name 写＋`{` 前 fail-leave；`#ifdef` **未开**（.x 体存在但不链接） | 无行为变化 |
| g-2 | `.x`：method 发现循环（FUNCTION/IDENT 捕获 fn_pos）＋签名机全 24 状态＋304 ent 偏移写；仍不链接 | 无行为变化 |
| g-3 | 开 `XLANG_PTHIN_SKIP_TL_BODIES_FROM_X` 区域 gate：hybrid 切 `.x` 体；C trampoline（镜像 commit）；探针矩阵＋矩阵＋双端 L2 | 行为切换 |

g-1/g-2 是「.x 侧预置体」波（同 P14b 先例——「~780 行已 T AUDIT 探针产品侧是 nop」的纯预置）；g-3 才是行为波。风险集中在 g-3 一处，回退＝关 define。

## 4. 探针矩阵（g-3 门）

1. 基础：无方法空体 `trait A {}`；单方法 `trait A { function f(); }`
2. 签名形状：`(a: i32)`, `(a: i32, b: []u8)`, `(): Ret`, `(): *T`, `(): []T`, `(): [N]T`, `(): [N][M]T`, `(): *T[N]`, `(): *[]T`, `(): *[N][M]T`
3. 默认体：`function f(): i32 { return 1; }`（has_default＋fn_pos 回读）
4. 混合：trait＋impl 同文件（reg 消费端联验：P12c impl-seen 匹配）
5. 失败路径：`trait`（无 ident）、`trait A`（无 `{`）、EOF 中断
6. 既有面：bstrict 中 trait 相关套件＋`std` trait 使用者编译

## 5. 风险与回退

- 最大风险＝签名机 24 状态转录笔误 → 探针矩阵 2 逐形状断言 ent 字段（C 侧 dump 比对 helper 只入测试）
- ent 布局 pin：seed `_Static_assert` offsetof ×~25；`.x` 偏移常量注释标「copies, not authority」
- 回退：g-3 关 define 即回 C 孪生；g-1/g-2 无行为面可留盘

## 6. 工作量估计

g-1 ~200 行 .x；g-2 ~1200 行 .x（机械转录＋偏移写）；g-3 ~80 行 C＋gate＋验证。总计 ≈2–3 个工作波。

## g-3 执行纪要（2026-09-13 · 波内回退 · 产品已恢复 c86a87926 基线）

g-3（开 gate + C trampoline）执行后 trait 探针全红，深挖定位出 **两个产品级 bug** 后按纪律回退；
差分 23/23（trait×16 + boundary×7，含负例）与矩阵 5/5 双验恢复。所有诊断资产如下。

### Bug 1（阻断 g-3）：asm 发射器大函数调用参数槽未初始化（P0）

- 症状：`parser_asm_skip_one_trait_method_sig_into_c`（~52KB 发射体）循环 4096 轮空转，
  peek 恒返同 token、pos 冻结；尾部 `parser_asm_lex_step_kind_c` 永不推进。
- 铁证：帧槽检查——peek 用 `[x29,#0x10]`（正确 lexer 指针），尾部 step 的 arg0 却从
  `[x29,#0xa18]` 装载＝**0（NULL）**；该槽是大链表达式临时量的共享槽（`add` 结果等反复写），
  到达路径从未存过 lex_inout → `step(NULL)` → 桥早退 no-op。
- UB 签名：同一二进制 lldb 下"正常"（栈垃圾恰为可用值）、冷栈直跑必坏——纯未初始化读。
- 归属：**asm 后端（调用参数 home 与表达式临时槽别名）**，须在后端根修，不在 P12g。
- 规避尝试与结果：极小 wrapper 函数 ✗（调用点编组仍读坏槽）；循环顶刷新本地副本 ✗；
  步进前置重构 ✗（修了推进但破坏 C 孪生的 `}` 留外层 / ASI 语义，且引入新回归）。
  —— 结论：**先修发射器，或把 sig 机拆小（≤~20KB/函数）**，勿再源级绕道。

### Bug 2（潜伏）：`-E` typecheck 宽松 vs `-c` 严格的不一致（危险面）

- `xlang_asm -E` 对「extern 调用未包 unsafe」放行（g-2b 起 sig 机里 ~18 处：
  条件内 `peek_int_val`、裸 `bk6 = builtin_ord(...)`）；`xlang -backend asm -c` 同文件
  立即报 `T001 extern call requires unsafe block`（fn 编号此刻才准确）。
- 已验证修法（下波直接重放）：peek 值提升为循环顶 unsafe 内 `iv` 本地、条件改用 `iv`；
  bk6 赋值逐个包 unsafe。修后 `-c` 过且 pure-asm 自发射成功（91455B .o）。
- 顺风发现：`xlang_asm -E` 与 `xlang -E` 的宽松面一致——**宽松放行 + 发射损坏的组合
  会静默产坏码**，建议后端 lane 补齐 `-E` 的同规则（或至少诊断）。

### g-3 下波重放清单（按序）

1. 重放 unsafe 清扫（iv 提升 + bk6 包裹）——`-c` 门槛过。
2. header 返回码 0/-1 区分（已写好：未消费/已消费失败，防 raw fallback 误触发）。
3. body `fn_line/fn_col` 接 `parser_asm_lex_peek_tok_line_c/col_c`（桥已存在，P5d）。
4. params 分支补尾 `else { saw_param_tok = 1; }`（C 孪生 L6625；裸 self 计参，否则 T001）。
5. **发射器根修或 sig 拆函数**（param-walk / ret-walk 两相位拆分，各自小函数），
   然后才是 trampoline 落地（trampoline 代码已验证过语义，见 git 历史本波工作树）。
6. 差分基线 `/tmp/p12g_ref.txt` 公式（23 探针集）可随时重录；隔离 harness 模式：
   `main(固定 token 流/真 lexer_gen) + seeds/pthin_skip_tl.from_x.c -D 门控 + 桥 + stub`
   5 分钟内可复现任何 sig 回归。

### 轨道事实（本波确认）

- Darwin 无 objcopy → `pure_asm_apply_weak_polish` 可失败回退 `-E→perl weak→prologue→cc` 转译；
  两条路径本波都实测出现过（PA 捕获 91455B / -E 捕获均有）。
- trampoline 语义已对 C 孪生逐路径核对（成功才 bump、registry-full 走 scratch、
  raw fallback 仅 hdr==0、dirty-slot 不读）；工作树版本随回退丢弃，见本 commit 父历史。

## 發射器槽 bug 定性反轉與實錘（2026-09-14 下午 · ban 二度上架）

**反轉**：上午三種形狀重建（簡單標記／表達式標記被嚴格 `-c` 攔／wrapper+li+marker）
在隔離 harness 均發射正確——一度以為 bug 不可複現、準備解除禁令。

**實錘**：解除禁令後產品鏈接**確定性全崩**（trait 探針全部 rc=139）——bug 真實且
**鏈接布局依賴**：隔離 harness（8 個 .o）布局碰巧落入良性垃圾（NULL 守衛/僥倖好值），
產品鏈接（68 .o）落入惡性值。lldb 逐步觀測蹦床 `out` 槽的污染序列：

```
0x100000001 → 部分寫 0x1001C6B6C → 0 → 0x170000030 → 0xb6c4(46788)
```

全部為 **4 字節部分寫**——`.x` 被調函數拿著**編組錯的垃圾參數指針**（大函數發射中
某 call-arg 臨時槽在到達路徑上未初始化）在蹦床幀上亂寫；最終 `*out` 以 0xb6c4 崩。
崩棧回溯：trampoline ← parser_skip_one_trait_into_glue（合法 C 調用方，入口 x0 正常）。

**對根修的約束（下波必讀）**：
1. 修復驗證**必須用產品鏈接**（或等布局 harness），隔離 harness 綠不代表產品綠。
2. 污染發生在被調 .x 函數執行期間（nexti 跨 call 前後槽值變化）——優先查
   body→sig 調用點的 ent_img/lex_inout 編組槽在到達路徑的初始化。
3. lane 有 .o 緩存慣性：恢復禁令後需 touch .x 強制重編才真正換軌。
4. 嚴格 `-c` typeck 能攔部分壞形狀（unsafe 違規面），但本次崩形狀全部 typeck 乾淨。

純 asm 軌道對本 .x 保持禁用（`XLANG_P12G_ALLOW_PURE_ASM=1` 可越）；產品恢復雙驗
（矩陣 5/5＋trait 探針綠）。

## 發射器機制定位（2026-09-14 傍晚 · FIX 波 · 根修線索齊備）

在崩態產品（pure-asm .o 鏈入）上完成靜態＋動態定位，機制釘死：

**調用編組的線性作用域違規**。發射器為 call 實參分配共享 staging 槽
（`str x0, [x29,#T]` 暫存、`ldr x0, [x29,#T]` 於 call 前取用），但 T 的「上次寫入」
按**線性指令序**跟蹤——不含支配關係。實據（sig 函數，52KB）：

- 284 個調用：152× p12g_store_i32＋101× p12g_load_i32＋4×4 copy_name＋其餘橋；
- arg0（ent_img，參數槽 #0x20）的取用槽分布於 0x280/0x368/0x3b8/.../0xc98 等
  **~30 個共享 staging 槽**，多數 staging 寫入距取用**數百條指令**（如 +3828 的調用
  讀 staging 於 +2160 才寫入的槽 0x870）；
- 若到達路徑經過別的分支臂（跳過 +2160 的寫入），槽為未初始化垃圾 → 被調方持
  垃圾指針寫入 → 調用方幀被 4 字節部分寫污染（前波實錘的 out 槽序列）。

body→sig 的編組本身乾淨（四參全部直取參數槽）；污染來自 sig 內部 ~261 個
ent 讀寫調用的 staging 跨臂復用。

**根修方向（下波，需專門 backend 波次＋全套回歸）**：
1. 首選：call 實參為 EXPR_VAR 時**直取 canonical home 槽**（local_offset 的參數/局部槽），
   不經共享 staging——找到 ELF call 實參 staging 的發射點（runtime_pipeline_abi.from_x.c
   的 EXPR_CALL mega 路徑）改為對 VAR 實參短路；
2. 備選：staging 槽按 call site 唯一分配（不復用）——幀增大但保證支配；
3. 驗證鐵律：隔離 harness 綠≠產品綠（布局輪盤）；必須產品鏈接＋trait 差分＋矩陣雙端。

產品已恢復轉譯軌（禁令生效＋touch 沖刷），矩陣 5/5＠`cd4ab947a`。

**下波根修靶心**（按序）：
1. 審計 `glue_sysv_spill_rax_rdx_to_frame_elf_c`（backend_call_dispatch.x:947）的

3. 復現注意：審計必須在崩態產品（pure-asm 鏈入）上做；每次重建後 sig 地址漂移，

## 根修進展二（2026-09-14 深夜 · 全零回退實證排除＋查找鏈全圖）

**全零回退排除**：在 `pipeline_asm_local_offset_c` 的全零名回退分支插樁 fprintf，
崩態產品（pure-asm 鏈入）跑 trait 探針——**回退從不觸發**。該回退非本次機制。

**查找鏈全圖**（實參 VAR 解析的權威路徑）：
```
for_call_args (ko==3)
 → glue_call_arg_resolve_var_stack_off_elf_c (.x @77331)
   → 快徑 glue_var_expr_stack_off_elf_c → glue_asm_local_var_stack_off_scoped (.x @48373)
       → asm_ctx_local_find_offset_scoped（塊作用域窄掃；miss 回退全表正掃）
   → 全 miss：命名 body-let lazy-append 後重解（glue_lazy_append_block_let_local）
```
兩個查找均**無**匿名回退；真 miss 返回 -1。

**剩餘頭號嫌疑（下波首查）**：快徑 miss（off<0）後落入通用
`pipeline_asm_emit_expr_elf_c` 的 VAR 分支——經 backend.x `local_offset`
（→ 帶全零回退的 pipeline_asm_local_offset_c，已證不觸發）——**miss 時該分支
