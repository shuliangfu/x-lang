## 0. 一句话结论

| 问题 | 结论 |
|------|------|
| **自举完成后，可以做编译优化与代码精简吗？** | **可以，而且应作为自举后的主线之一。** |
| **顺序对不对？** | **对。** 先「正确、可复现、双端钉盘」→ 再「快、小、干净、可维护」。 |
| **现在（2026-07-24）该不该做？** | **不该抢主航道。** 现行主线仍是 **Cap residual pure**；优化/大瘦身会放大爆炸半径、双权威与假绿窗口。 |
| **自举「刚完成」第一件事是什么？** | **稳住基线**：多轮完整 L4 + 全量 bstrict，确认无回退；再开优化轨。 |
| **优化原则** | **有测量才改**；**一条债一层一个 commit**；精简时区分「可删临时」与「产品语义」。 |

## 1. 决策框架：为什么必须「先自举、后优化」

### 1.1 自举的目标 vs 优化的目标

| 阶段 | 目标 | 成功判据 | 失败代价 |
|------|------|----------|----------|
| **自举期** | 编译器能正确编译自己与产品面；可复现；双端绿 | tip L4 双端 `run-all-bstrict`；工程轨 + 产品轨分清 | 假绿 → 雪崩（14/15 号教训） |
| **优化期** | 编译更快；生成代码更好；源/产物更瘦；结构更清晰 | 基准不回退 + 语义门禁仍绿 | 为瘦代码或微优化弄回退自举 |

**自举目标**是「先能正确编译自己、稳定可复现」；**完成之后**再做：

1. **性能优化**（编译速度、生成代码质量）  
2. **代码精简与重构**（去重、清债、统一抽象）  
3. **结构整理**（模块边界、命名、文档）

这是健康编译器项目的**正常、重要**下一步，不是「可有可无的打磨」。

### 1.2 为何不能现在并行大开优化轨

| 风险 | 说明 |
|------|------|
| **归因污染** | residual 叶（parse/typeck/codegen/fs）与「热路径加速」同 commit 时，红了分不清语义还是优化 |
| **双权威放大** | 优化若只改 `.x` 或只改 seed/glue，自举后立刻漂移（G.7） |
| **假绿窗口** | 优化常动 glue / WPO / regalloc；旧 `.o` 最易藏；须 L4，但自举期资源应优先 residual |
| **语义回退** | 为删路径/合并函数若动到仍被矩阵依赖的行为，会把刚稳住的钉盘打掉 |
| **与 leave-off 抢航道** | 当前 soft：untyped-let、trait、reentrancy、asm `!=` 等；优化不应淹没这些地图 |

**对照**：语言级 `string` 糖、closure 深工程等同理——**自举轨优先**（见 `基础类型缺口与自举时机分析.md`）。优化轨同样**后置**。

### 1.3 分阶段总表（建议节奏）

| 阶段 | 重点 | 说明 |
|------|------|------|
| **现在** | 自举 + Cap residual | 正确性、钉盘稳定、双端绿；日常 L2 + 整波/日终 tip L4 |
| **自举刚完成** | 稳住基线 | 再跑几轮完整 L4（mac+Ubuntu），确认无回退；钉盘写死「自举完成 SHA」 |
| **随后** | 优化 + 精简 | 编译器提速、减体积、清历史债、去双权威残留 |
| **再往后** | DX / 对外 | CLI 风格统一、错误信息、文档、生态站 P1 内容 |

```text
Cap residual / host residual 主闸门关闭
        │
        ▼
  多轮 L4 钉盘（无回退）  ←── 自举「完成」的产品定义入口
        │
        ▼
  P0：基线测量 + 可删清单审计（只读/文档）
        │
        ▼
  P1：安全精简（死代码、临时路径、备份二进制策略）
        │
        ▼
  P2：编译速度（有测量的热路径）
        │
        ▼
  P3：生成代码质量（regalloc / isel / WPO 深化）
        │
        ▼
  P4：结构 / DX / X-ABI 等中长期
```

## 3. 「自举完成」闸门（进入优化轨的前置条件）

未满足前，**禁止**把主航道改成优化/大精简。

### 3.1 硬条件（建议写入进度 KPI）

| # | 条件 | 说明 |
|---|------|------|
| 1 | Cap residual / host residual **主闸门关闭** | leave-off soft 可列清单，但不得挡「能正确编自己」 |
| 2 | **双端 tip L4** 全绿 | mac + Ubuntu；`remaining_o=0` 起编；本波 `xlang`/`xlang_asm`/`xlang-c` |
| 3 | **全量 bstrict** 全绿 | 以当时脚本数为准（现 129）；无 BEST_EFFORT / 假绿 env |
| 4 | **多轮无回退** | 自举完成 SHA 上再跑 **≥2～3 轮** 独立 L4（或日终连续绿），防「刚绿就漂」 |
| 5 | 工程轨与产品轨 **同 SHA 叙事** | 不单靠 prove N / Stage2 子集宣称完成 |
| 6 | 可选：G-07 发布 prep gate | `G-07-selfhost-release.md`；tag 策略另议 |

### 3.2 「完成」后第一周：稳住基线（P0）

| 动作 | 产出 |
|------|------|
| 冻结 **baseline SHA** + 日志路径 | 进度文「自举完成钉盘」 |
| 建立 **编译性能基线**（见 §5） | `tests/baseline/` 或 analysis 表：wall / phase_ms / RSS / .o size |
| 建立 **生成代码质量基线** | hello/stdlib 用例 size、关键路径、既有 regalloc quality TSV |
| **可删/须留** 审计清单（只读） | 见 §6；不先大批量删 |
| 明确优化轨纪律 | 同 skill：一条债一层、seed 同 commit、SHARED 双端 |

**禁止**：完成当天立刻「大删 seed / 重写 pipeline / 默认开激进 WPO」。

## 4. 自举完成后适合做的优化方向

### 4.1 编译速度（compiler throughput）

| 方向 | 项目内落点 | 备注 |
|------|------------|------|
| **减少不必要的遍历** | typeck 二次 walk、WPO edge collect、import 同步 | 先用 `XLANG_COMPILE_PHASE_TIMING` 看谁吃墙钟 |
| **数据结构** | AST pool 增长、符号表、overload 候选集 | 对齐 `comp-typeck-hotpath` 历史；禁无测量乱改 cap |
| **分配与 RSS** | `driver_arena_static` 等巨石 BSS（5GB 调查） | **优先改增长策略**，不是先砍正确性检查 |
| **并行化安全部分** | 独立模块 typeck / codegen（无共享可变 AST 时） | 后置；先证明无数据竞争契约 |
| **增量编译** | `archive/comp/comp-incr-compile-*.md` | 产品级增量是中期；勿与 residual 语义债混做 |
| **dogfood 自编加速** | 编译器编 `compiler/src/**` 的 wall time | 自举 dogfood 是最真实基准之一 |

**测量入口（已有）**：

```bash
XLANG_COMPILE_PHASE_TIMING=1 $XLANG -o /tmp/hello examples/hello.x
# stderr: parse_ms=… typeck_ms=… codegen_ms=… total_ms=…
```

### 4.2 生成代码质量（code quality）

| 方向 | 项目内落点 | 备注 |
|------|------------|------|
| **寄存器分配** | asm 7.3 · `glue_asm73_*` · quality TSV | 减 spill、改进 cfg merge |
| **指令选择** | isel 专项 + peephole | 在现有 `-O` / peephole 上深化 |
| **WPO 深化** | reach DCE、const-spec、跨模块内联（配合 X ABI） | 默认策略与 opt-in 分清；Linux 金标 |
| **布局 / ABI** | sret、slice dual-GP、fixed array | residual 已大量修补；优化期做「质量」而非「能跑」 |
| **安全证明驱动优化** | BCE / noalias（`安全与性能.md`） | **证不出就回退**；禁止猜 alias |

### 4.3 代码精简（source / tree hygiene）

| 方向 | 示例 | 谨慎度 |
|------|------|--------|
| **删自举临时路径** | 一次性 patch 脚本、实验 bridge、仅证明用 stub | 中：先确认门禁无引用 |
| **双权威收敛** | seed ↔ `.x` ↔ `strict_minimal` glue 三份 score/emit | **高**：必须 G.7 有则补全、同 commit |
| **调试桩 / 备份二进制** | `xlang_asm.pre_*`、`*.bak`、多份 `xlang_asm.*` | 低：工作树卫生，勿当语义删 |
| **合并重复逻辑** | parser/typeck/codegen 相似 helper | 中：先检索再合并，禁半残权威旁第二套 |
| **统一命名与模块边界** | 已有 wave382 `length` 全写类决策 | 中：与 docs 同步 |
| **兼容层退役** | 仅服务旧 pin / 旧 stage 的包装 | 高：矩阵/脚本依赖须先清 |

### 4.4 体积与依赖

| 方向 | 说明 |
|------|------|
| **std/core/compiler 精简** | 去掉不再需要的兼容 API；on-demand 入链保持「不用不链」 |
| **seed 体积** | seeds ~35M 是冷启动税；长期目标是 **`.x` 权威 + 更薄 pin**，不是永远复制 mega C |
| **链接面** | `labi_*` 门控已是权威；精简时勿退回「全 std 硬链」 |
| **运行时 glue** | crypto/net/… 按需；空桩外置（wave383 crypto 先例）继续 |

### 4.5 可维护性（改一处、行为清晰）

| 方向 | 说明 |
|------|------|
| **单一权威路径** | mangle、overload score、skip emit、field access — 继续 G.7 清分叉 |
| **PLATFORM 注释** | 优化常动 ABI；G.8 防 mac 假绿 / Ubuntu UNDEF |
| **英文 JSDoc 注释** | 触碰 `.x` 时 G.9；利于日后 `xlang doc` |
| **文档与 KPI** | 优化轨也要「进度两文」；大债才写问题地图 |

### 4.6 DX / 对外（更后）

| 方向 | 说明 |
|------|------|
| CLI 风格统一 | `xlang` / `xlang_asm` / `xlang-c` 用户叙事 |
| 诊断质量 | 错误码层、恢复、LSP（`archive/exc/*`） |
| 文档与网站 | 生态站 P1 在自举完成后才加重（见 `xlang-生态网站规划.md`） |
| 语言糖 | `string`/`str`、closure 等 — **编译器稳后**再开（已有专项分析） |

## 5. 有测量的优化（强制方法）

### 5.1 基线维度（建议最小集）

| 维度 | 度量 | 固定用例（示例） |
|------|------|------------------|
| **编译墙钟** | `time` / phase_ms | `examples/hello.x`、`tests/option/main.x`、编一个 std 模块、编 `compiler/src/parser/parser.x`（dogfood） |
| **阶段拆分** | parse / typeck / codegen ms | `XLANG_COMPILE_PHASE_TIMING=1` |
| **编译器 RSS / 峰值** | `/usr/bin/time -l`（mac）或 `/usr/bin/time -v`（Linux） | 同上；对照 5GB 调查 |
| **生成代码大小** | `.o` / 可执行 `size`、`.text` | hello；带 import 的小程序 |
| **生成代码速度** | 用户程序运行微基准 | 仅当优化目标是 runtime 时 |
| **regalloc / isel 质量** | 既有 quality TSV + disasm 门禁 | `run-asm-73-gate` 等 |
| **正确性闸门** | 产品矩阵 + 全量 bstrict | **每次优化波必过**；SHARED 双端 |

### 5.2 优化 commit 纪律

```text
1. 记录基线数字（SHA + 日志路径）
2. 单点改动（一层：typeck 或 codegen 或 glue，不搅）
3. 复测：基准 + 最小探针 + 产品矩阵
4. 整波/日终：L4 + bstrict（与自举期相同节奏）
5. 无提升或回归 → revert，不「先合再调」
```

### 5.3 禁止的「优化」

| 禁止 | 原因 |
|------|------|
| 关 typeck / 安全检查换速度 | 假绿 + 安全债（`安全与性能.md`） |
| soft-skip / BEST_EFFORT 糊墙钟 | 14 号结构再现 |
| 只改 seed 不改 `.x`（或反之） | 双权威 |
| 无基准的「感觉慢就重写」 | 不可回归 |
| 批量改 std 写法顶编译器慢 | G.3 假修 |
| 猜 noalias / 删边界检查 | wrong code |

## 6. 精简清单：可删 vs 须谨慎

### 6.1 相对可删（精简期优先审计）

| 类别 | 例子 | 条件 |
|------|------|------|
| **工作树垃圾** | `xlang_asm.pre_*`、`*.bak*`、本地实验二进制 | 确认未入库或 gitignore；勿当「源码精简」KPI |
| **明确废弃脚本** | 只服务已关 phase 的 one-shot patch | 门禁与 Makefile 无引用 |
| **死调试开关路径** | 长期 `if (0)` / 未接线 env | 全库检索后删 |
| **重复 thin 包装中的业务拷贝** | 包装应只转调权威 | G.7 合并后删副本 |
| **文档硬编码第三套 ABI** | 与代码不一致的表 | 改指向代码权威 |

### 6.2 须谨慎（默认不删，先收敛）

| 类别 | 例子 | 原因 |
|------|------|------|
| **产品矩阵语义** | overload 评分、link on-demand、STRING 解码 | 一删即红 |
| **seed pin** | `seeds/*linux.x86_64.c` | 冷启动金标；只可「同语义变薄」不可「先砍再说」 |
| **strict_minimal glue twin** | overload score 等 | 与 typeck 必须同语义；删一侧前须证明另一侧已是唯一入链 |
| **runtime glue / platform** | panic、net、crypto | PLATFORM 分叉；Ubuntu 真值 |
| **leave-off soft 行为** | untyped-let 拒、reentrancy last-wins | 文档契约；改 = 语言决策 |
| **bstrict 脚本期望** | 123/129 套行为 | 禁为绿改期望 |

### 6.3 双权威收敛策略（精简核心）

```text
目标状态（长期）：
  权威语义 ∈ .x（parser/typeck/codegen/…）
  seed / glue = 冷启动或 ABI 镜像，同 commit 同语义，体积尽量薄
  禁止：.x 一套 + seed 一套 + glue 硬编码第三套

收敛步骤：
  1) 地图：每个能力写清「权威符号 = 文件+函数」
  2) 检索：近义名 / seed / strict_minimal / 脚本旁路
  3) 有则补全权威；调用方只转调
  4) 删除或弱化副本；门禁证明副本未再入链
  5) tip L4 双端
```

### 6.4 历史 mega / hybrid 路径

自举方法主线是 Cap → R 真迁 → M 去 pin。  
**优化期**可把「仍 hybrid 的 rest」与「已 pure 但仍留 C 壳」列入 **体积债表**，但：

- **不得**为减字节破坏 prove / R2 已 IDENTICAL 的模块而不跑金标；  
- **优先**真迁与 pin 关闭，而不是手写「更快的 C 旁路」。

## 7. 建议工作包切分（自举完成后）

> 包与包之间可并行调研，**合入仍一条债一层**。

### 包 A — 基线与观测（1～2 周量级，视人力）

- 固化 phase timing + wall + RSS 表（hello / option / dogfood parser）  
- 生成代码 size / 关键 regalloc 指标快照  
- 输出「热点 top-N」报告（typeck vs parse vs codegen vs link）

### 包 B — 安全精简（低风险）

- 工作树与 scripts 卫生  
- 死代码 / 未引用 stub  
- 文档与命名统一（延续 length 全写纪律）  
- **不**动 seed 语义

### 包 C — 编译器吞吐

- 按 A 的热点改：减少 walk、缩候选集、arena 策略  
- 每波：基准 + 矩阵；SHARED 双端

### 包 D — 生成代码质量

- regalloc / isel / peephole 深化  
- WPO 默认策略评估（opt-in → 有限默认）  
- 安全证明类优化（BCE 等）单独立项

### 包 E — 双权威与 seed 瘦身（高价值、高风险）

- 分模块：parser pin → typeck pin → codegen pin  
- 每模块：同 commit 对齐 → 证明镜像可删/可生成 → L4  
- 目标：seeds 目录**可解释、可再生**，非「考古博物馆」

### 包 F — 结构与 DX

- 模块边界（pipeline / driver / runtime 职责）  
- CLI / 诊断 / 文档  
- X ABI P1（见专项）；语言糖另表

## 8. 与「现在」主线的边界（防抢跑）

| 现在（Cap residual）允许 | 现在禁止当作「优化主线」 |
|--------------------------|---------------------------|
| residual 叶根修正确性 | 默认打开激进 WPO/并行 typeck |
| 顺手删**本叶引入**的死调试打印 | 大批量删 seed / glue 副本 |
| 进度文记一笔「优化期候选」 | 开多周重构 branch 与 residual 混推 |
| 读-only 基准探测（不改产品） | 为基准改语义或关检查 |
| G.7 发现重复 → **本叶相关**才合并 | 「全局去重」大扫除 |

**leave-off soft（示例，随进度变）**：untyped-let、trait、reentrancy last-wins、asm `i32 !=` 等 — **不是**优化包的第一目标；要么进 residual，要么进独立语言债。

## 9. 风险与回滚

| 风险 | 缓解 |
|------|------|
| 优化回退语义 | 每波矩阵 + 邻域探针；坏则 revert commit |
| 只 mac 绿 | SHARED 必 Ubuntu L4（dead_strip 假绿） |
| seed 变薄后冷启动失败 | 保留可再生流程；pin SHA 可回滚 |
| 并行/增量引入难复现 bug | 后置；先单线程正确吞吐 |
| 精简误删门禁依赖 | 删前 `rg` + 跑相关 gate + 全量 bstrict |
| 优化与安全对立 | 证得出才优化；失败回退（`安全与性能.md`） |

**回滚默认**：`git revert` 单主题 commit；禁止在坏优化上叠补丁糊绿。

## 11. 结论（可直接贴进度/评审）

1. **自举完成后，完全应该进入「优化编译器 + 精简代码」阶段。**  
2. **现在**继续 **Cap residual + 钉盘纪律**；优化只做候选登记与只读测量，不抢主航道。  
3. **自举刚完成**：多轮 L4 稳住基线 → 再建测量与可删审计 → 再系统做吞吐 / 代码质量 / 双权威收敛。  
4. **全程**带着测试与钉盘：优先有测量的优化；精简区分临时与产品语义；**一条债一层**；G.7/G.8/L4 不放松。  
5. 项目内**已有** WPO、regalloc、phase timing、内存调查、安全-性能契约 — 优化期是**深化与收敛**，不是另起炉灶。
