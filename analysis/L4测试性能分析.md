# L4 / bstrict 测试性能分析

> **日期**：2026-08-10  
> **范围**：产品 L4 真冷（`./xbuild l4`）+ 全量 `run-all-bstrict`（129 scripts）  
> **方法**：日志墙钟 + 阶段锚点 + 微基准 + 脚本结构；**不改代码**，只出问题地图与优化方向  
> **金标机器**：Ubuntu x86_64（`ubuntu-remote-server`）  
> **开发机**：macOS Darwin arm64（Apple M5 Max · 18 核 · 64GB，本波实测）

---

## 0. 一句话结论

| 判断 | 说明 |
|------|------|
| **编译（冷重建）不是主瓶颈** | 双端 step5–7（bootstrap + g05 + L2 矩阵）都在 **~4–5 分钟**，几乎打平 |
| **主瓶颈是 step8 全量 bstrict** | Mac **~31 min** / Ubuntu **~7 min**，占 Mac 全 L4 的 **~88%** |
| **Mac vs Ubuntu ≈ 3× 全墙钟、≈4.5× bstrict** | 同 SHA `d79a368b2`；不是「Mac 编译器链更慢一个数量级」 |
| **编译器单次 `-o` 与测试编排都有债** | 单测路径重、串行、Darwin 主动 sleep、无并行、重复 ensure/链接、clang 警告噪声 |
| **211 分钟是异常墙钟，不是常态** | 常态 Mac L4 **~30–36 min**；`5acd137bd` 的 211m 应视为休眠/挂起/机器空闲导致的墙钟膨胀 |

**能否优化？能。**  
优先改 **测试编排与测量**（可拿回数分钟～十余分钟），再改 **编译器/链接热路径**（降低单次 `xlang -o` 成本，放大到数百次调用）。  
**不要**用软跳过 / 改期望 / 砍金标 bstrict 项来「糊快」。

## 1. 实测基线（同日、可复现）

### 1.1 权威入口

```text
./xbuild l4
→ compiler/scripts/product_l4_true_cold.sh
  step1–4  擦 .o / 二进制 / pin seed
  step5    bootstrap-driver-seed
  step6    g05_prepare_and_relink --sync → xlang_asm
  step7    product L2 matrix（5 项）
  step8    XLANG_BSTRICT_SKIP_BUILD=1 tests/run-all-bstrict.sh  （129 scripts）
  不跑 xlang check
```

### 1.2 同 SHA `d79a368b2` 双端

| 端 | 全 L4 wall | bstrict | 冷重建+矩阵（推算） | 日志 |
|----|------------|---------|---------------------|------|
| **Ubuntu Linux-x86_64** | **11m36s** | **7m00s（420s）** | **~4.6 min（276s）** | `/tmp/xlang_l4_Linux_d79a368b2.log` |
| **macOS Darwin-arm64** | **35m42s** | **31m17s（1877s）** | **~4.4 min（265s）** | `/private/tmp/xlang_l4_Darwin_d79a368b2.log` |

推算方式：`全 wall − bstrict 合计秒`。  
Mac 另有 `xlang_asm mtime=18:28`、L4 `started=18:24:20` → 冷链约 **4 min** 量级，与推算一致。

### 1.3 阶段占比（`d79a368b2`）

```text
                    Ubuntu              Mac
step1–4  wipe/pin   可忽略              可忽略
step5–6  冷重建     ~4 min              ~4 min     ← 双端打平
step7    L2 矩阵    秒～几十秒          秒～几十秒
step8    bstrict    7 min (60%)       31 min (88%) ← 差距几乎全在这里
────────────────────────────────────────────────
total               11.6 min            35.7 min
```

**结论**：谈「L4 慢」时，**先谈 bstrict，再谈冷编译**。冷编译在双端已经不是差异源，也不是 Mac 半小时的主因。

### 1.4 Mac 历史样本（排除异常）

| 日志 SHA | bstrict 合计 | 备注 |
|----------|--------------|------|
| 0ce5dc658 | 13.6 min | 偏快（可能部分失败早退或路径不同） |
| 52665b5c9 | 23.3 min | |
| 多数全日样本 | **26–31 min** | 中位约 **28 min** |
| **d79a368b2** | **31.3 min** | 全绿 full L4，**35.7 min** 墙钟 |
| **5acd137bd** | **207.8 min** | **异常**：墙钟 211m；与同机其它样本差一个数量级 |

**异常说明**：`date +%s` 墙钟会计入笔记本睡眠、进程挂起、系统休眠。  
`5acd137bd` 与同日其它 10 个样本（13–31 min bstrict）不可比；**分析性能时以 ~30 min 常态为准**，211m 只记作「测量陷阱」，不作为瓶颈证据。

### 1.5 单次编译微基准（辅助）

| 场景 | 结果 |
|------|------|
| Mac `xlang_asm -backend c examples/hello.x -o …` ×5 | 墙钟约 **18s** → **~3.6 s/次**（含 host-cc 链接与 clang 警告刷屏） |
| 机器 | Apple **M5 Max** · **18** 核 · **64GB**（算力充足，不是「机器太弱」） |
| Ubuntu | 20 核 · 61Gi；同 SHA L4 bstrict **~3.3 s/script 平均** |

若 bstrict 路径上有 **数百次** 完整 `xlang … -o`，则「单次 3–4s」直接解释 Mac 二十多分钟的有效计算时间。

## 2. 瓶颈分层：编译 vs 测试

```text
┌─────────────────────────────────────────────────────────────┐
│ L4 wall clock                                               │
│  ┌──────────────────┐  ┌──────────────────────────────────┐ │
│  │ A. 冷编译/链接    │  │ B. 测试编排 (bstrict)             │ │
│  │ bootstrap+g05    │  │ 129 scripts × 串行                │ │
│  │ ~4–5 min 双端    │  │ Mac 31 min / Ubuntu 7 min         │ │
│  │ 占比 Mac ~12%    │  │ 占比 Mac ~88%                     │ │
│  └────────┬─────────┘  └────────────────┬─────────────────┘ │
│           │                             │                     │
│           ▼                             ▼                     │
│  A1 大 seed C 编译              B1 每 script 多次 xlang -o   │
│  A2 串行 leaf rebuild           B2 Darwin 强制 sleep ~4 min  │
│  A3 过滤 .o / pure-ld           B3 ensure 36 个 std/core .o  │
│                                 B4 每测独立 cc 链接 + 警告   │
│                                 B5 零并行、无分片、无计时仪  │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 A 层：冷编译（有成本，但不是「半小时」主因）

**做什么**：全擦后重建 `xlang` / `xlang_asm`（seed pin → bootstrap-driver-seed → g05）。

**贵在哪**：

1. **巨型 seed C**：`codegen_gen` ~917KB、`typeck_gen` ~778KB、`parser_gen` ~528KB —— 冷编译必吃满。  
2. **大量 leaf `.o` 串行 ensure**（pipeline / sat / lsp / user-asm / host-cc stubs…）。  
3. **日志极冗长**（Mac step5  alone 可占日志 **7 万行**），本身也有 I/O 与 tee 成本，但相对墙钟仍小于 bstrict。

**为何双端打平**：Mac 与 Ubuntu 都在 ~4–5 min 完成同一冷菜谱 →  
当前硬件上 **冷链已可接受**；继续抠冷链 ROI 低于抠 bstrict。

**仍值得中期优化的点**（不阻塞测试加速）：

- leaf 构建并行（`Ninja`/`make -j` 语义的 shell 并行 ensure，需守 G.7 单权威）  
- 减少重复 catalog 解析（已有 cache，可查是否每子进程重热）  
- 大 gen 文件增量 / 分 TU（产品债，非测试专属）

### 2.2 B 层：bstrict 测试（主战场）

**结构事实**：

| 项 | 值 |
|----|-----|
| `BSTRICT_SCRIPTS` | **129** 个 `run-*.sh` |
| 调度 | **严格串行** `for script; do … done` |
| 每 script 默认 | 可能：ensure `.o`、多次 `xlang build/-o`、再 `cc`、再跑二进制 |
| 仓库 `tests/run-*.sh` | ~**882**；`.x` 样例 ~**1194**（全库；bstrict 是子集） |
| L4 时 | `XLANG_BSTRICT_SKIP_BUILD=1`（不再 bootstrap），但仍 **ensure 36 个 std/core `.o`**（冷擦后全空） |

**Mac 平均**：1877s / 129 ≈ **14.6 s/script**（含 sleep、skip、轻量脚本被重脚本拉高均值）。  
**Ubuntu 平均**：420s / 129 ≈ **3.3 s/script**。  
比值 **~4.5×** —— 与「Mac 单次 hello ~数秒、Ubuntu 单次更短」同方向。

#### B1. 单测 = 完整编译链接（编译器成本 × 调用次数）

典型 `run-io.sh`：连续多次

```bash
$XLANG build -L . tests/io/xxx.x -o /tmp/xlang_io_...
```

每次都是：**parse → typeck → codegen(C) → 写临时 .c → host clang/cc → link 一堆 std `.o` → 跑**。  
没有「复用上一次 pipeline 的增量对象」「共享链接 driver」「预热常驻编译器进程」。

日志侧信号（Mac `d79a` bstrict 段）：

- `run-io.sh` / `run-fs.sh` / `run-fmt-std.sh` 等 **日志行数极高**（io 4k 行级）  
- **1600+** 条 clang `warning:`（括号比较等）—— 警告刷屏拖慢 cc 与 tee  
- 这是 **测试触发的编译路径成本**，不是「测试逻辑本身算得慢」

#### B2. Darwin 强制 cooldown（纯浪费墙钟）

`tests/run-all-bstrict.sh`（Darwin）：

```bash
run-types-gate.sh) sleep 5
heavy: ub/io/crypto/vector/thread/net/json) sleep 15
*) sleep 1
```

对 **129** 个 script 粗算：

- 默认 1s × ~120 + heavy 15s × 7 + types 5s ≈ **~231 s ≈ 3.9 min**  
- 约占 Mac bstrict 的 **~12%**，占全 L4 的 **~11%**

这是历史 **OOM Killed:9** 防护（连续 `xlang_asm -o` 内存尖峰）。  
在 **64GB M5 Max** 上是否仍需要默认 1s/15s，**值得用数据重标定**；关掉或降到 0/2s 是 **零风险试探**（先只在本机 env 覆盖，不改默认）。

环境变量已存在（无需改代码即可试）：

```bash
export XLANG_BSTRICT_DARWIN_COOLDOWN=0
export XLANG_BSTRICT_DARWIN_HEAVY_COOLDOWN=0
export XLANG_BSTRICT_DARWIN_TYPES_COOLDOWN=0
./xbuild l4   # 或只跑 bstrict
```

#### B3. 冷擦后 ensure 36 个 std/core `.o`（串行）

bstrict 开头（非 `SKIP_STD_ENSURE`）：

- `process/string/path/net/…/error/test` + `core/types|result|option|…` 共 **36** 个  
- 每个：`xlang -E` 类路径 + `cc -c` + formal_mod 符号后处理（Mac 无 objcopy 时还有 wrapper 生成）  
- **串行 for 循环**，冷 L4 必付全价  

这部分同时属于 **编译** 与 **测试前置**；只发生在 bstrict 入口一次，量级通常 **分钟级**，不是 31 分钟的全部，但是 **可并行优化点**。

#### B4. 零并行 / 无分片

- 无 `xargs -P`、无 jobserver、无「按目录 shard」  
- Ubuntu 7 min 已可接受；Mac 31 min 时并行是最大杠杆之一  
- **难点**：共享 `std/*.o`、临时文件名、端口（net）、全局 `/tmp/xlang_*` 易撞车 → 要 **隔离 TMPDIR + 只读共享 .o**

#### B5. 测量不足（导致误判，如 211m）

- L4 只有 **总 wall** + bstrict **总耗时**  
- **没有** per-step、per-script 计时  
- 无法自动排出 Top10 慢脚本 → 优化只能靠猜或人工扫日志  

这是 **第一优先工程债**（低风险、高信息增益）。

## 3. Mac 为何比 Ubuntu 慢 ~3–4.5×？

同菜谱、同 script 列表，冷重建却打平 → 差距来自 **bstrict 执行效率**，不是「Mac 不会冷编译」。

| 因子 | 估计贡献 | 说明 |
|------|----------|------|
| **单次 `xlang -o` + host-cc 更慢** | **大（主因候选）** | Mac ~3.6s/hello；×数百次 → 二十余分钟。Ubuntu 平均 script 仅 3.3s（含多用例） |
| **Darwin cooldown sleep** | **~4 min 固定** | ~12% bstrict；易 env 验证 |
| **clang 警告刷屏** | **中** | 1600+ warning 行；拖 cc 与日志 I/O |
| **Mac formal_mod / 无 objcopy 路径** | **小～中** | ensure 时 wrapper 生成；bstrict 内若反复 ensure 会放大 |
| **arm64 跳过部分 script** | **略减负** | vector/net/dual-chain 等 skip，仍 31 min → 剩下的更重 |
| **磁盘 / 杀毒 / Spotlight** | **未定量** | 可能；需 `fs_usage` / 对比排除目录后复测 |
| **算力不足** | **否** | M5 Max 18 核 64G；瓶颈是 **串行 + 单调用重** |

**注意**：Mac 金标职责是 SHARED 对照；**链接完整性金标仍是 Ubuntu**。  
加速 Mac 的目标是 **开发反馈环**，不是用 Mac 取代 Ubuntu 结案。

## 4. 优化方向（按 ROI / 风险排序）

### 4.0 原则（与 AGENTS / 自举闸门一致）

1. **禁止** soft-skip、改测试期望、砍 Ubuntu 金标项来「变快」。  
2. **日常** 继续 L2/L3；**结案** 仍 L4；优化的是 **同样闸门跑得更快**。  
3. **一条债一层**：编排 / 编译器热路径 / ensure 并行 分开落地与验证。  
4. 先 **加测量**，再改行为；每项优化用 **同 SHA 双端** 对比 wall。

---

### P0 — 测量与分层门禁（1–2 天工程 · 几乎不降覆盖）

| 项 | 做法 | 预期收益 |
|----|------|----------|
| **P0.1 per-step 计时** | `product_l4_true_cold.sh` 每 step 打 `elapsed_s=` | 一眼区分冷链 vs bstrict |
| **P0.2 per-script 计时** | `run-all-bstrict` 每个 script 前后 `date +%s`，结束排序 Top20 | 定位真·慢脚本（io/fs/import…） |
| **P0.3 导出 JSON/CSV** | `/tmp/xlang_bstrict_timing_<sha>.csv` | 趋势、回归、异常墙钟（睡眠）可识别 |
| **P0.4 分层命令文档化** | 已有：`./xbuild l4 --rebuild-only` / `--no-bstrict` / full | 日常只跑矩阵；结案 full |

**验收**：同一次 L4 日志能回答「谁占 80% 时间」。

---

### P1 — 编排层加速（改测试壳 · 不降语义）

| 项 | 做法 | 预期收益 | 风险 |
|----|------|----------|------|
| **P1.1 Darwin cooldown 重标定** | 64G 机器默认降为 0 或 heavy=2；OOM 再回退 | **立刻 ~4 min**（Mac） | 内存压力机器可能再 Killed:9 → 用 env 灰度 |
| **P1.2 压制 cc 警告噪声** | 生成 C 或测试 cc 行加 `-Wno-parentheses-equality` 等（**只限测试/host-cc 包装**，勿藏产品错误） | 中：减 I/O 与 cc 时间 | 需避免掩盖真错 |
| **P1.3 ensure 36 `.o` 并行** | `xargs -P "$(nproc)"` 或分池并行 ensure；依赖已有 `ensure_std_c_o` | 冷 bstrict 开头 **数分钟→数十秒** | 竞态写同路径；需按输出路径隔离 |
| **P1.4 稳定 `/tmp` 名与 TMPDIR** | 每 script `TMPDIR=$(mktemp -d)` | 为并行铺路 | 中 |
| **P1.5 bstrict 分片** | `BSTRICT_SHARD=1/4` 四进程互不重叠 script 集 | 理想 **近线性**（Mac 31→~10 min 量级，受共享磁盘限制） | 高：全局状态、端口、`.o` |
| **P1.6 进程内复用编译器** | 长期：`xlang --daemon` / 多文件 batch driver | 大（削启动+重复加载） | 高；产品能力 |

**建议落地顺序**：P0 → P1.1（env 实验）→ P1.2 → P1.3 → 再评估是否值得 P1.5。

---

### P2 — 编译器 / 链接热路径（降单次 `-o` 成本 · 放大 ×N）

这些是 **真·编译性能**，优化一次惠及 L2 探针与全部 bstrict。

| 项 | 方向 | 说明 |
|----|------|------|
| **P2.1 host-cc 链接集合** | 审计 `-o` 是否每次链过宽 std `.o` | 过宽 link 在 Mac ld 上更痛 |
| **P2.2 生成 C 体积与警告** | 少发无用括号比较；减少重复 preamble | 直接减 cc 时间 |
| **P2.3 formal_mod 后处理** | Mac wrapper/rename 路径 profiling | ensure 与 multi-file 热路径 |
| **P2.4 pipeline 常驻 / mmap 缓存** | 标准库元数据、catalog blob 进程内缓存 | 降每次启动固定成本 |
| **P2.5 冷链 leaf 并行** | bootstrap/g05 ensure 并行 | 把 4 min → 2 min；**次要** |

**目标量级**（拍脑袋需 P0 数据校准）：  
若 Mac 单次 hello 3.6s → 1.5s，且调用次数不变，bstrict 有望 **31 min → ~15 min** 量级。

---

### P3 — 策略与工作流（不改覆盖的「体感加速」）

| 场景 | 建议命令 | 时长量级 |
|------|----------|----------|
| 改 formal / std 符号 | 单 gate + `l2-matrix` | 分钟 |
| 改编译器语义 | `./xbuild l4 --no-bstrict` 或 Ubuntu 探针 | Mac ~5 min / Ubuntu ~5 min |
| **结案 / SHARED** | Ubuntu `./xbuild l4` **必跑**；Mac full **按需** | U ~12 min / M ~36 min |
| 禁止 | 把 211m 异常当基线；叠多个并行 L4 互踩 | |

**工作流优化往往比抠 10% cc 更快**：  
「一天 10 次 full Mac L4」→ 改为「1 次 Ubuntu L4 + 多次 L2」可省数小时，且不降金标质量。

## 5. 「编译慢」还是「测试慢」？—— 精确回答

| 说法 | 是否成立 |
|------|----------|
| 「编译器太慢所以 L4 半小时」 | **半对**：冷编译只占 ~12%；但 **测试里嵌了成百上千次完整编译** |
| 「测试框架慢」 | **对**：串行、sleep、无分片、无 per-test 计时、重复 ensure |
| 「两边都有瓶颈」 | **对**，但权重是 **B（测试编排 × 单次编译成本）≫ A（冷重建）** |
| 「先优化 seed 大文件编译就能 L4 减半」 | **否**；冷链双端已 ~4 min，减半只省 ~2 min |
| 「先优化 bstrict 编排 + 单次 -o」 | **是**；这是唯一能把 Mac 36 min 打到 15–20 min 区间的路径 |

更准确的公式：

```text
T_L4 ≈ T_cold_rebuild + Σ_i ( T_xlang_o(case_i) + T_cc_link(case_i) + T_run(case_i) )
         + T_darwin_sleep + T_ensure_std_serial

T_cold_rebuild ~ 常数 4–5 min
Σ T_xlang_o     ~ 主导项（次数 × 单次成本）
T_darwin_sleep  ~ 0–4 min（可配置）
```

## 6. 建议路线图（可执行）

### 第 0 周（本周可做 · 零/低代码）

1. **记录常态基线**（已有）：Mac full **~36 min** / bstrict **~31 min**；Ubuntu **~12 / 7 min**（`d79a368b2`）。  
2. **丢弃 211m 样本** 作为性能基线。  
3. **env 实验 Darwin cooldown=0** 跑一波 bstrict-only，量是否稳定省 ~4 min、有无 Killed:9。  
4. **日常** 默认 `./xbuild l2-matrix` 或 `./xbuild l4 --no-bstrict`；结案才 full。

### 第 1 周（P0 测量）

1. step 与 script 级计时落地。  
2. 产出 Mac/Ubuntu Top20 慢脚本表。  
3. 用表决定是先砍 sleep、先并行 ensure，还是先优化某个 `run-*.sh` 的重复 `-o`。

### 第 2–3 周（P1 编排）

1. cooldown 默认策略按机器内存分档。  
2. ensure 并行。  
3. 测试 cc 警告策略。
