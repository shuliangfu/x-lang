## 1. 「自举完成」之后世界变了什么

### 1.1 完成前后的目标切换

| | **自举期（现在）** | **自举完成后** |
|--|-------------------|----------------|
| 主目标 | 编译器能正确编自己 + 产品面双端可复现 | **人能信赖地用语言写软件** |
| 成功判据 | L4 + 129；v2==v3；无 Makefile 权威 | 同样绿 **+** 用户路径短、错信息可读、库好用、编译够快 |
| 主要用户 | 作者自己 / 自举 agent | **外部用户 + 未来 std 作者** |
| 禁止 | 语言糖抢 residual；大优化淹没根因 | 在无测量时「为快而改」；无测试床加语言特性 |

### 1.2 完成日必须已经为真的前提（否则不算「完成后」）

摘自 `C迁移追踪.md` 终局三义（缺一不可）：

1. **MG**：编排不依赖 Makefile 权威（xbuild / 等价）  
2. **BC**：编译器自身 TU 不靠 host-cc 编译业务 C  
3. **PC**：用户默认 `-backend asm`，不默认 exec host-cc  
4. **语义**：v2==v3（及可选 D-03）  
5. **产品**：双端 tip L4 + `run-all-bstrict` 129 钉盘  

> 若仅「prove 绿」或「只删了根 Makefile」→ **不算**完成，下文路线图**不启动**。

## 3. `xlang test` 能不能放第一位？

### 3.1 今日实现是什么（避免误解）

| 项 | 现状 |
|----|------|
| CLI | `xlang test [script.sh]` 已挂子命令（`compiler/src/driver/test.x` → `driver_run_test`） |
| 默认行为 | 文档/README：默认跑 **`tests/run-all.sh`**（或指定脚本路径） |
| **不是** | Rust/`#[test]` 自动发现 · 过滤 · 并行 · JUnit 报告 · `assert!` 语言内建 |
| 仓库真验收 | 大量仍是 **shell gate**（`run-all-bstrict.sh`、各 `run-*-gate.sh`）+ `XLANG=./compiler/xlang_asm` |

因此：

- 若「第一位」= **把用户跑测试的入口统一成 `xlang test`，并让它成为 129/矩阵/CI 的唯一推荐路径** → **✅ 应该，且适合作为 P1 头条**。  
- 若「第一位」= **立刻做完整语言级测试框架 + 再开语言特性** → **❌ 顺序过重**；应 **T0→T3 分期**，语言特性在 **T1 可重复绿** 之后并行。

### 3.2 为什么测试入口适合紧接 P0（P1 头条）

| 理由 | 说明 |
|------|------|
| **语言完善的前置床** | 每加一个语言能力（string / trait / async）必须有**可重复的红绿探针**；否则又回 14 号假绿 |
| **用户信任的第一触点** | 外来者不会跑 129 条 shell 名；`xlang test` 是「语言像成品」的第一印象 |
| **替代 Makefile 后的空位** | 删 make 后，测试不能继续「只有 `make test`」；xbuild + `xlang test` 必须接棒 |
| **已有半实现** | 子命令与 driver 已在，**补全成本低于从零开 string** |
| **与 bstrict 收敛** | 把 129 套件收成 `xlang test --suite product` 一类，减少「脚本知识」债 |

### 3.3 为什么**不能**用「语言特性」抢在测试床之前

| 风险 | 说明 |
|------|------|
| 无统一 runner | 特性合入只靠临时 `/tmp` 探针 → 双端/回归易漏 |
| 诊断与失败格式未定 | 用户看到的是 shell 碎日志，不是语言错误模型 |
| 与优化/精简抢归因 | 同时改 codegen 优化 + 新语法 + 测试脚本 → 红点无法归层 |

### 3.4 `xlang test` 升级阶梯（T0–T3）

| 阶段 | 名称 | 目标形态 | 建议时机 | 验收 |
|------|------|----------|----------|------|
| **T0** | 现状固化 | `xlang test` = 调 shell；文档写清默认脚本与 `XLANG=` | 自举完成前可做文档 | help/README 与行为一致 |
| **T1** | **产品入口第一公民** | `xlang test` 默认 = 产品矩阵 + 可选 `--bstrict` / `--suite`；**不**再要求用户记 `run-all-bstrict.sh` 路径；退出码与摘要统一 | **P1（自举完成后第一批）** | 双端：`xlang test` 与 SKIP_BUILD 全量 bstrict 同结论 |
| **T2** | 工程内建 | 发现 `tests/**/*.x` / `#[test]` 或 `test` 函数约定；`assert_eq` 等测试 API（std.test）；过滤 `-k` / 并行 | **P2 与语言 assert 同期** | 示例包 `xlang test` 无 shell |
| **T3** | 生态级 | JSON/JUnit 报告、coverage 钩子、`xlang.toml [test]`、CI 模板 | **P3–P4** | registry 示例 CI 可抄 |

**推荐回答用户原话**：

> **自举完成后，在 P0 基线钉死后，可以把「把 `xlang test` 做成真正的第一测试入口（T1）」放在完善语言之前的第一工程位。**  
> 完整语言级测试框架（T2）与 `string` 等语言糖同属 P2，**并行但不要压过 T1**。

## 6. P2 细项：语言完善 + 优化 + std（三轨并行）

> **门禁**：每条语言能力 **先红探针进 `xlang test` suite**，再合入；SHARED 双端；大面改 L4。

### 6.1 P2a — 语言能力（「完善 X 语言」主清单）

| 序 | 能力 | 动机 | 依赖 | 建议顺序 |
|----|------|------|------|----------|
| L1 | **测试断言 API**（`std.test` / `assert_*`） | 支撑 T2；库作者第一需求 | P1 T1 | **最先** |
| L2 | **语言级 `string` / `str` + 插值** | 文档已标「自举后」；用户第一痛 | 布局 RFC · 与 `std.string` 单权威 | 紧随 L1 |
| L3 | **错误信息与 span 质量** | 学习曲线 | explain 码表 | 与 L2 并行 |
| L4 | **泛型 / trait / dyn 收口** | 自举期 soft 债（bounds、dyn） | typeck 硬失败策略 | 中 |
| L5 | **闭包 / 函数指针完整** | 与 Cap-fn-ptr、线程回调 | 阶段 10 能力若自举期已部分完成则续 | 中 |
| L6 | **unsafe 边界与安全子集** | 见 `安全路线.md` | 诊断 | 中 |
| L7 | **const / CTFE 诚实性** | 消 mac CTFE 假绿纪律债 | 求值器 | 中 |
| L8 | **async / Io trait 落地** | 见 async RFC；自举后阶段 2 | 执行器注入 | 后置 |
| L9 | **宏 / 反射（若要）** | 高爆炸半径 | 稳定语法面 | 很后 |

**语言轨纪律（强制）**：

1. G.7：一种能力一条权威路径（含 seed 若仍存在）。  
2. 文档与实现同 commit（`docs/02` 等）。  
3. **禁止**半残 keyword 冒充（尤其 string）。

### 6.2 P2b — 编译器性能与生成质量

完整分析见 [`自举后编译优化与代码精简分析.md`](自举后编译优化与代码精简分析.md)。此处只定顺序：

| 序 | 主题 | 第一步 |
|----|------|--------|
| O1 | **测量基线** | 打开/固化 `XLANG_COMPILE_PHASE_TIMING`；固定 bench 集（hello / option / 编译器自编） |
| O2 | **编译速度** | 针对 top 阶段（parse/typeck/codegen）有数据地改 |
| O3 | **生成代码** | regalloc / isel / WPO 深化；默认策略谨慎 |
| O4 | **体积与精简** | seed 考古删除、死路径、双权威残留 |
| O5 | **内存** | 编译器自身峰值（历史 5GB 类问题） |

### 6.3 P2c — std / 平台 / 安全

| 序 | 主题 | 说明 |
|----|------|------|
| S1 | std 缺口按用户场景排 | 见 `docs/07-内置与标准库.md`「部分完善」；**有测试再扩 API** |
| S2 | 网络 / TLS / 压缩 | 自举期 glue residual 若已 .x 化则补 API 稳定 |
| S3 | freestanding / 内核子集 | 与安全路线 Debug/Release 溢出策略对齐 |
| S4 | Windows 产品路径 | 自举后才升「第三金标」候选（见 Windows 时序文档） |

## 11. 与「完善优化 xlang 语言」的对应关系

用户目标：**自举完成后完善优化语言**。本文拆成可执行层：

| 用户口语 | 本文落点 |
|----------|----------|
| 语言好不好写 | P2a string/str、泛型、诊断 |
| 语言安不安全 | P2a unsafe/安全子集 · P2c |
| 编译器快不快 | P2b |
| 标库齐不齐 | P2c |
| 好不好测 | **P1 xlang test T1 → P2 T2** |
| 好不好发库 | P3 toml · P4 registry |
| 好不好装 | P1 教程 · P3 xbuild |

**测试不是「与语言对立的旁支」**：它是语言完善的**质量闸门**；所以 **T1 可以（也应该）排在多数语言糖之前**，但 **不能**排在 P0 基线之前。
