## 0. 为什么换成多系统并行（必读）

**以前（物理机双系统）**：Ubuntu 与 Windows 装在同一台机器上，SSH 别名甚至共用同一个 IP（历史上 `192.168.8.156`）。**同一时刻只能开一个系统**；要测另一边必须 **重启切换**，等开机、再 SSH，非常不方便。Agent 还曾被要求「能连 Ubuntu 时不要假定 Windows 可连」——那是双系统时代的约束。

**现在（Proxmox 并行模拟机）**：五套测试 OS 是五台虚拟机，外加本机 macOS。**不必重启物理机切换**。日常 **只开一对**（Win11 + Ubuntu 26／`ubuntu-server`），要测 22/24/Win10 再 `qm start`。金标／真值仍是 Ubuntu x86_64；Windows 是 **三端硬闸必测端**（非金标）。变的是 **可达性 + 日常放行须三端 L2**，不是「Win 取代 Ubuntu」。

| | 旧：双系统 | 新：并行 VM |
|--|-----------|-------------|
| 同时在线 | 不能（重启切换） | **能**（配置允许并行；日常只开一对，见 §1.5） |
| 登录 | 看当前启动的是哪套 | `ssh <别名>` 选目标（关机的先 `qm start`） |
| 测 Win 又测 Ubuntu | 重启一次 | 开两个终端（日常 Win11 + Ubuntu 22） |
| 金标 | Ubuntu | **仍然是 Ubuntu**（**2026-09-14 起日常金标＝26.04**；22/24 转兼容轨，同金标纪律） |

实验室分两层：**管理机**（Proxmox，开关/改配置）和 **模拟机**（五台客人 OS，跑测试）。管理机 **不跑** x-lang 产品测试。

### 1.5 资源与日常开机（2026-09-13）

宿主机 `pve`：i9-12900H（20 线程）、**62G** 内存。客人配置写成 8 核 / 24G **不等于** 空转就吃满这些。

| 状态 | CPU | 内存 | 说明 |
|------|-----|------|------|
| **关机**（`qm stop`） | 0 | 0 | 只占 50G 虚拟盘。Win10 / Ubuntu 24 / Ubuntu 26 日常保持关机 |
| **开机空转 · Ubuntu** | 接近 0 | 很少（实测 QEMU RSS ~1G） | 8 个 vCPU 在睡；balloon 把没用的页还给宿主机 |
| **开机空转 · Windows** | 接近 0 | **仍高**（Win11 空转 QEMU RSS 常 15–20G） | 8 核同样在睡；但 Win11 自己会摸很多页，balloon **还不干净** |
| **正在编译 / L4** | 最多 8 核忙 | 可涨到 24G | 这才是「高配提高测试效率」的时刻 |

**为什么不配 32G：** 两台同时跑 32G = 64G，超过宿主机 62G，会把 PVE 自己换进 swap / OOM。日常一对（Win11 + Ubuntu 22）用 **最大 24G** 是上限：48G 客人 + 宿主机自己，还留一点余量。第三台不要同时开。

**日常开机对（当前）：**

| VMID | 名 | 日常 |
|------|----|------|
| 101 | win11 | **开** |
| 104 | ubuntu26 | **开**（金标，2026-09-14 起） |
| 100 | win10 | **关** |
| 102 | ubuntu22 | **关**（兼容轨；要用再 `qm start`） |
| 103 | ubuntu24 | **关**（兼容轨） |

换测 24 / 26 / Win10 时：先 `qm start` 目标，测完 `qm stop`；**不要**五台一起开。配置已经都是 8 核 / 最大 24G，开机即同样规格。

**空转会不会拖慢宿主机 / 别的虚拟机：**

- **CPU：不会。** 空转的 vCPU 几乎不占物理核；编译时才抢。
- **内存：Ubuntu 空转几乎不影响；Windows 空转会占一大块。** 所以日常只留一台 Windows（Win11），不要 Win10 也开着。
- **关机的三台：完全不影响** CPU/内存。

禁止：`qm set --memory 32768` 还同时开两台；禁止为了「方便」把 24/26/Win10 也常开。

## 2. 谁跑什么测试（角色，不是「每台都全量 L4」）

| 机器 | 应当跑 | 不要当成 |
|------|--------|----------|
| **PVE `pve` / `192.168.8.150`** | 模拟机生命周期：`qm start/stop/set/list` | x-lang 金标、在宿主机上编编译器 |
| **macOS** | 开发、日常 L2 探针、SHARED 时本机矩阵；**唯一 `git commit`** | Ubuntu 链接完整性真值（mac `-dead_strip` 会藏 UNDEF） |
| **Ubuntu 26（金标）** | 产品金标：L2 矩阵、**L4 真冷**、`tests/run-all-bstrict.sh`、`tests/run-all.sh` | 「三台都绿才算金标」——金标机按纪律跑完即金标 |
| **Ubuntu 22 / 24（兼容轨）** | 周期性兼容回归（gcc 11/13 线） | 代替金标做放行（除非金标不可用） |
| **Windows 11** | **三端 L2／L4 必测端**：`product_l2_matrix`／hybrid／`tests/run-bootstrap-bstrict-windows-gate.sh` | 自举**金标**、全量 bstrict **真值**（那是 Ubuntu，不是 Win） |
| **Windows 10** | 同上，Tier 2 对照 | 日常三端硬闸（优先 Win11） |

**日常放行硬闸（2026-09-22）**＝**三端同 tip L2**：macOS＋`ubuntu-server`（Ubuntu26 金标）＋`windows-server`（Win11）。任一红先修。  
**结案／谈自举**＝三端 L4；**金标／真值仍是 Ubuntu**（全量 bstrict）；mac／Win 必须通过，**不能**取代 Ubuntu。  
**Win 底座过渡**：bootstrap／g05 未通前不得宣称三端硬闸已绿——详见 **[自举验证.md](./自举验证.md) §8.4**。  
**源码铁律未变**：只 Mac commit/push；客机只 git pull；禁 scp 源码；不默认 bstrict／升钉。

## 3. 源码同步（铁律，未改）

| 方向 | 正确 | 禁止 |
|------|------|------|
| mac → 五台模拟机 | mac `git commit` + `git push` → 对端 `git pull --ff-only` | `scp` / `rsync` **源码树** |

## 4. 测试依赖（全面分析）

测试不是「有个 gcc 就能跑」。产品路径是 `./xbuild` + 大量 `tests/*.sh`；冷启动仍要宿主 **C 编译器**；std/io、compress、sqlite 要 **开发库**；脚本要 **bash / python3 / perl / make**。权威包清单对齐 CI：`.github/workflows/ci.yml` 与 `HOW_TO_TEST.md`。

**各机已经装上的具体版本（实测）见 §7**；下面是「为什么要这些、缺了怎么补」。

### 4.1 分层

| 层 | 做什么 | 硬依赖 |
|----|--------|--------|
| **宿主工具链** | 编 `xlang` / `xlang_asm` / `xlang-c`、链用户程序 | `cc`/`gcc`、`ld`/`as`/`objdump`/`nm`、`make`（叶 `.o` / 考古残留） |
| **脚本运行时** | `tests/*.sh`、`xbuild`、g05、bstrict | `bash`、`python3`、`perl`、`gawk`/`awk`、`sed`、`diff`、`git` |
| **Linux std 开发库** | `std.io`（liburing）、compress（zlib/zstd/brotli）、`std.db.sqlite` | `liburing-dev zlib1g-dev libzstd-dev libbrotli-dev libsqlite3-dev` |
| **诊断** | CI / 失败现场 | `file`、`strace`、`curl`、`xz`、`pkg-config`、`lsof`（可选） |
| **Windows 额外** | PE 路径、临时文件、MinGW | Git Bash、`CC=gcc`、短路径 `TEMP=C:/xlang_tmp`、`gcc` 来自 w64devkit |

**不需要**（本实验室刻意不装，降低占用）：Windows 桌面 / 显卡 / 登录画面、MSVC 整套、完整 MSYS2 发行版、Docker 里的 Alpine 专用 VM、cmake/nasm/clang 作为默认门。

CI Windows job 用 **MSYS2** 装 `make gcc python3 gawk zlib-devel brotli`。本实验室用更轻的 **Git for Windows + w64devkit**（已有 gcc/make/ld），SSH 壳为 Git Bash，语义对齐 hybrid 探针，**不是**再装一套 MSYS2。

### 4.2 Ubuntu 22 / 24 / 26（三台相同包）

```bash
sudo DEBIAN_FRONTEND=noninteractive apt-get update -qq
sudo DEBIAN_FRONTEND=noninteractive apt-get install -y --no-install-recommends \
  build-essential git python3 perl gawk pkg-config file \
  binutils strace curl xz-utils lsof \
  liburing-dev zlib1g-dev libzstd-dev libbrotli-dev libsqlite3-dev \
  locales
sudo locale-gen en_US.UTF-8 zh_CN.UTF-8
```

| 包 | 为何 |
|----|------|
| `build-essential` | gcc/g++/make/libc-dev；`cc` 是 gcc 别名 |
| `git` | **唯一**源码同步 |
| `python3` / `perl` / `gawk` | 测试与 codegen 脚本 |
| `liburing-dev` | `std.io` 异步 uring |
| `zlib1g-dev` `libzstd-dev` `libbrotli-dev` | `std.compress` / io |
| `libsqlite3-dev` | `std.db.sqlite`；没有则走 stub（`DB_NOT_IMPL`），金标应装真库 |
| `binutils` | `objdump`/`nm`/`ld` 验 `.o` / UNDEF |
| `strace` `file` `curl` `xz-utils` | CI 与失败现场 |
| `locales` | 避免 `LC_ALL=zh_CN.UTF-8` 却无 locale 数据，脚本被 locale 警告干扰 |

无桌面、无 snap。产品入口：`./xbuild`（**不要**再发明 `make -C compiler` 编排；叶 `.o` 才走残留 make）。

### 4.3 Windows 10 / 11（Git Bash + w64devkit）

| 组件 | 路径 / 值 | 为何 |
|------|-----------|------|
| Git for Windows | `C:\Program Files\Git\` | `git`、**SSH 登录壳** `bin\bash.exe`、`usr\bin` 里的 `perl`/`sed`/`awk`/`diff` |
| w64devkit | `C:\w64devkit\bin` | `gcc`/`cc`/`make`/`ld`/`as`/`objdump`/`nm` |
| Python 3 | 用户 PATH 中的 `python`/`python3` | `tests/*.sh` 调 python |
| `CC` | `gcc` | 脚本默认 `cc`；Windows 必须显式 gcc |
| `TEMP`/`TMP` | `C:\xlang_tmp`（短路径、无空格） | `xlang-c` 调 gcc 时路径过长/含空格会截断；Win32 `CreateFileA` 不认 `/tmp` |
| `~/win_xlang_env.sh` | 用户主目录 | PATH / `CC` / `TEMP`；**不** `cd`。SSH 登录默认家目录 |
| OpenSSH DefaultShell | `C:\Program Files\Git\bin\bash.exe` | 远程命令与交互都是 bash，测试脚本可直接跑 |

**不要**用 `git-bash.exe` 当 SSH 壳（会拉 mintty GUI）。  
**不要**用 PowerShell 当默认壳跑 `tests/*.sh`。

已知 Windows 限制（弱符号 / SAC / `.exe` 后缀 / 无 `cc`）见 [Windows平台限制与测试指南.md](./Windows平台限制与测试指南.md)，本文不重复。

### 4.4 macOS（开发机，不在五台模拟机里）

### 4.45 新机/重克隆冷启动（无产品二进制时）

`compiler/xlang-c` / `bootstrap_xlangc` 是 **gitignored 构建产物**——新克隆机上没有，直接 `./xbuild` 会因 `build_tool_main.from_x.c` 种子已退役而失败。正确入口（egg 流程，已在 26.04 实测）：

```bash
./xbuild bootstrap-driver-seed   # 装蛋：pinned 种子 → ./xlang + xlang-c
./xbuild                          # 常规增量构建
```

### 4.5 跑测试前的仓内依赖（源码，不是 OS 包）

1. 对端已 `git pull --ff-only`，SHA 与 mac 已 push 的 `origin/self-hosting` 一致  
2. 冷启动 / L4 仍要 seed：`compiler/seeds/*.linux.x86_64.c`（产品 pin）  
3. **禁止**用旧 `compiler/xlang_asm_stage1` 或跨 SHA 二进制当本波验收  
4. 谈自举 / 结案：Ubuntu 上 **L4 全擦 `.o` + 重链** 再矩阵 / bstrict（见自举验证手册）
